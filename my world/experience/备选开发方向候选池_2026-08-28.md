# my world｜备选开发方向候选池

## 0. 定位

本文件记录过去 SillyTavern / The World / DSH 与真实旧游戏中已经出现过、被证明有潜在价值，但**当前 Roadmap 尚未授权实施**的产品能力。

它的用途是防止遗忘，同时避免另一种错误：

> **“过去做过 / 讨论过” != “现在必须重新做”。**

本文件不是 CURRENT Roadmap、不是 Task DAG、不是 Implementation Authority。

总原则：

> **保留方向，不预付平台成本。**
>
> **真实玩法需求 → 最小实现 → 第二消费者 → 再抽象协议。**

### 2026-08-28 已从候选池提升为 CURRENT 的能力

以下不再属于 Deferred：

- Character Card 作为第一代 Primary Source；
- Expansion Pack 作为第一代 Primary Source，数量 `0..N`；
- Exactly 1 Player Character + 0..N Guaranteed NPC Character 建局语义；
- Protagonist Control Mode：Full / Light / Narrative；
- Managed Source Library / immutable Source generation；
- Multi-Game / Game Library；
- asset-only New Game path。

它们的当前 Authority 见 Product / Architecture / Roadmap，不再从本候选池读取。

---

## 1. World Variant / Historical Profile

### 价值

旧三国局真实存在“正史基线 / 演义倾向”等世界口径选择。同一 World Pack 可能需要少量互斥或可选 Source profile。

### 当前不做

第一代优先通过不同 Entry/T0 或最小 World 参数表达；不建立万能 variant/profile DSL。

### Revisit trigger

首个真实 Pack 证明 Entry 不能自然表达世界口径，而拆成多个 Pack 又明显不合理。

---

## 2. Explicit Opening Cast / Opening Placement

### 价值

当前 Guaranteed NPC 只保证角色属于本局，不保证第一幕出现。未来可能需要玩家或 Entry 指定“这个角色必须在开场同场”。

### 当前不做

不把 `bound_only / opening_character / player_character` 三角色用途系统重新暴露给玩家。

### Revisit trigger

真实 World/Character UAT 反复出现“我选了某 NPC 就是想第一幕见到他”的明确需求。

优先考虑 Entry-owned opening cast / placement，而不是重新扩张角色 role taxonomy。

---

## 3. Opening Scenario / Prologue Runtime

### 价值

过去已经识别：静态 T0 后完全等待玩家会导致“没有目标、没有第二场景、没有新人物”的自锁；开场需要尽快出现值得回应的局势。

### 当前处理

G4 World Pack 支持 lightweight Entry/T0；G4 First Playable 必须产生具体可玩的真实 AI Opening；G5 再负责 authoritative semantic materialization / World Initiative。

### 当前不做

不建立 Beat graph、precondition DSL、branch tree、剧情收敛状态机、PROLOGUE_SCENARIO_MODE。

### Revisit trigger

G5 World Initiative 已成立后，真实作者需要 authored prologue；Owner 先真实创作至少一份 Opening Scenario 再决定 machine representation。

---

## 4. Player-known Entity Directory / Long-lived Dossier

### 价值

```text
Current Scene Visible Characters
!=
Player-known Character Directory
```

玩家认识过的人物应跨场景长期保留，但只显示玩家合法知道的信息。

### 当前不做

Guaranteed NPC / Source Character 不自动进入 People UI；完整 Directory owner 与 UI 留给 G5 Knowledge Provenance / G6 RPG Experience。

### Revisit trigger

玩家实际认识多个离场人物后，当前三栏 UI 已无法可靠表达“认识过谁 / 最后知道什么”。

---

## 5. Reference Library / Large Lore Retrieval

### 价值

大型历史、制度、地理、文化、技术和研究资料不适合无限塞进 World Pack；资料库作为可复用参考资源层有长期价值。

```text
Library bound
!= Runtime relevant
!= Player known
!= Model visible
```

### 当前不做

不建设 RAG/vector database、资料库管理 UI、自动语义检索、Reference Provider 或 Library external protocol。

### Revisit trigger

- 多个真实 World Pack 出现大量重复参考资料；
- G7 长上下文验证证明静态 Source slicing 不足；
- Creator 真实创作过程需要按需研究资料。

---

## 6. Asset Family / Bundle / Distribution Lock

### 价值

旧资产仓库用 Asset Family 聚合一部作品使用的 World / Character / Expansion，并以 Bundle 表达某次交付的版本锁。对内容发行和“一键安装作品组合”有价值。

### 当前不做

G4 已有 exact Composition + immutable Source generation；不额外建设 Bundle manager、作品发行协议或 package resolver。

### Revisit trigger

真实作品需要把多个 Source 作为一个可重复分发单元安装给其他玩家。

---

## 7. Historical Source Version Picker

### 价值

高级玩家/作者未来可能希望用旧版本 World / Character / Expansion 开新 Game。

### 当前处理

Managed Source Library 内部保存旧 generation 供已有 Game 精确继续。

### 当前不做

New Game UI 默认只显示当前安装版本，不让多个 sibling version 同时进入普通 selection surface。

### Revisit trigger

真实用户明确需要“用旧版资产创建新局”，且 exact-version UI 的复杂度值得承担。

---

## 8. Expansion Feature / Module Fine-grained Selection

### 价值

复杂 Expansion 可能包含多个 feature/module，玩家未来可能只启用部分能力。

### 当前不做

第一代 Expansion 以 pack-level `0..N` selection 为主，先证明真实 Runtime effect；不重做旧项目复杂 feature/module toggle tree。

### Revisit trigger

至少一个真实 Expansion 因包内功能互斥/可选而无法用 pack-level enablement 表达。

---

## 9. Conversational Creator / AI-assisted Authoring

### 价值

历史上形成的成熟方向：

```text
Structured Creator Workspace
+
AI Authoring Conversation
→ typed Draft edits
→ deterministic Validator
→ visible ChangeSet / Undo
→ user Save / Publish
```

AI 可以编辑 Draft，但不能静默发布 Source Asset；Conversation 不是资产事实源；无 Provider 时 Creator 仍应可手工使用。

### 当前不做

Creator 正式留到 G8。G4 先证明 hand-authored Source 真能 install → select → create → play。

### Revisit trigger

G8 Authoring 开始前，先让 Owner 用真实 Source contract 手工/轻工具创作资产，复盘字段负担后再冻结 Creator UX。

---

## 10. Gameplay Map System

### 价值

长期可能需要 Region / Place / Scene、道路/水路、可达连接、旅行时间、地图标记、势力范围与玩家已知地图投影。

### 当前处理

G4 只支持 authored map asset/source reference + Asset Resolution。

### 当前不做

不建立 topology graph、寻路、旅行 simulator、战术地图、地图编辑器或 procedural geography platform。

### Revisit trigger

真实游戏产生持续地理移动与位置维护需求，仅靠 Narrative + authored map 图片无法支撑理解/决策。

---

## 11. Battle / Mechanic Dedicated Surfaces

### 价值

战斗、经营、政治、关系等高频机制最终可能需要专门 UI，而不是全部塞进 Narrative。

### 当前路线

G4 Expansion 先证明 Runtime effect；G6 根据真实 mechanic consumer 建 Internal Declarative UI Host。

### 当前不做

不在 G4 预建战斗面板、骰点控制台、政治仪表盘或 external UI DSL。

### Revisit trigger

G5 某机制在连续 Owner UAT 中高频出现，并且纯文本交互明显降低理解/操作效率。

---

## 12. Advanced Save / Timeline Product Surfaces

候选包括：

- Timeline browser；
- arbitrary per-turn rewind；
- backup browser；
- branch picker；
- revision history；
- 更丰富 Save manager。

G3 已证明底层 Recovery/branch/backups，但第一代产品刻意不把内部调试历史全部暴露给玩家。

### Revisit trigger

长局 Owner UAT 反复证明 named Save + recent Recovery 不足以纠正常见错误，且新增 UI 的认知成本明显低于恢复收益。

---

## 13. No-asset / AI Blank-world Game Creation

### 价值

未来可能允许玩家只输入一句设定，由 AI 协助生成 World / Character / Entry 后开始游戏。

### 当前不做

第一代正式冻结 asset-only creation。原因是旧项目为了支持自由 Creation 曾引入复杂 semantic materialization、degraded/no-key path、placeholder world 和大量 UAT 修复。

### Revisit trigger

Primary Source 建局、Creator 和 Living World 都稳定以后，真实用户明确需要“无现成资产快速开局”。

若重启该方向，应优先复用正式 Creator 生成 Source，再走同一 Final Create，而不是建立第二套 Runtime Creation truth。

---

## 14. Online Pack Store / Cloud / Account

### 价值

长期可能需要 Pack 分享、更新、云存档、跨设备、作者发布与市场。

### 当前不做

第一代坚持 local-first / single-player-first，不引入账号、服务器、在线商店、远程代码包或云同步复杂度。

### Revisit trigger

Standalone Alpha 已长期稳定，且真实用户/发行需求出现。

---

## 15. Autonomous Creator Agent / Cross-asset Operations / Auto Research

候选包括：

- 跨多个资产批量重构；
- 长时间 autonomous authoring agent；
- 自动联网研究；
- 通用任务调度器；
- speculative vector/RAG platform。

### 当前不做

这些能力不是 Creator 首版条件。

### Revisit trigger

基础 Creator 经过真实 UAT 后，有明确重复劳动和高价值自动化需求，并且简单 typed tools 无法解决。

---

## 16. 重新进入 Roadmap 的检查表

任何候选要进入 CURRENT 前，至少回答：

```text
1. 当前真实玩家/作者遇到了什么问题？
2. 不做它的实际损失是什么？
3. 是否已有更简单能力能解决？
4. 是否有第二个真实消费者，还是只为未来想象？
5. 它会不会压缩 AI GM 的自然创作空间？
6. 普通错误是否可以用 Retry / Save / Recovery 更便宜地处理？
7. 是否会制造新的第二事实源、万能协议或框架森林？
8. 最小可试玩 vertical 是什么？
9. Owner UAT 如何判断它真的更好？
```

通过后，先更新 CURRENT Roadmap / Architecture，再创建 Task Packet；不能反过来先实现再找理由。
