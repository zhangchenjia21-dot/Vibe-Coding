# my world｜备选开发方向候选池

## 0. 定位

本文件记录过去 SillyTavern / The World / DSH 与真实旧游戏中已经出现过、被证明有潜在价值，但**当前 Roadmap 尚未授权实施**的产品能力。

它的用途是防止遗忘，同时避免另一种错误：

> **“过去做过 / 讨论过” != “现在必须重新做”。**

本文件不是 CURRENT Roadmap、不是 Task DAG、不是 Implementation Authority。任何候选只有在出现明确真实需求、第二消费者、Owner UAT 反馈或当前阶段 blocker 后，才重新进入 Product Definition / Architecture Gate。

总原则：

> **保留方向，不预付平台成本。**
>
> **真实玩法需求 → 最小实现 → 第二消费者 → 再抽象协议。**

---

## 1. Character Card 独立 Source Asset

### 价值

过去已经形成“一人一卡”的重要人物资产方式，能够跨 World Pack 复用并维护人格、目标、私密经历、决策倾向等长期定义。

### 当前不做

G4 v0.1 只需要 World Pack 内 lightweight character source seeds；不现在冻结完整 Character Card 外部协议、版本迁移、导入导出和 Creator UI。

### Revisit trigger

- 第二个以上 World Pack 真实复用同一重要角色定义；
- G5 NPC Agency 证明 World Pack 内 seed 明显不足；
- G8 Authoring 开始外部化内容协议。

---

## 2. Expansion Pack / Mechanic Composition

### 价值

旧《乱世三国2》真实使用过多组可选机制：战斗、政治、关系、名望、家族、组织、身体状态、判定、战争、穿越系统等。机制组合能够显著改变一局游戏的玩法。

### 当前不做

G4-03 `Game Creation Composition v0.1` 不一次恢复完整 Expansion selector / dependency graph / feature-module runtime。World Pack 只保留最小 data-only mechanic declarations。

### Revisit trigger

- 第一个真实 World Pack 必须允许玩家启用/禁用某机制才能正常建局；
- G5-05 Meaningful Choice / Mechanics Integration 出现第二个真实机制消费者；
- G8 正式进入 Expansion authoring contract。

---

## 3. World Variant / Historical Profile

### 价值

旧三国局真实存在“正史基线 / 演义倾向”等世界口径选择。同一 World Pack 可能需要少量互斥或可选 Source profile。

### 当前不做

不在 G4-02 先设计万能 variant/profile DSL。G4-03 v0.1 只冻结 Pack generation + Entry + protagonist seed。

### Revisit trigger

首个真实三国 Pack 建局时，Owner 明确需要在同一 Pack 内选择世界口径，而拆成两个 Pack 明显不合理。

---

## 4. Protagonist Control Mode

### 价值

旧游戏真实使用过 Light control：玩家决定方向和关键承诺，GM 可代行旅途/日常琐事，玩家可随时收回控制。它可能改善自由文本 RPG 的节奏与操作负担。

### 当前不做

不把控制级别写进 G4-03 v0.1 的必需 Composition，也不建立复杂代理权模式矩阵。

### Revisit trigger

G5 Owner UAT 反复出现“琐事太多 / GM 不敢推进”或“GM 代行过多”的真实体验问题。

---

## 5. Opening Scenario / Prologue Runtime

### 价值

过去已经识别：静态 T0 后完全等待玩家会导致“没有目标、没有第二场景、没有新人物”的自锁；开场需要尽快出现值得回应的局势。

### 当前处理

G4 只保留 lightweight Entry / T0 Source Seed；真正 Opening Situation / World Initiative 属于 G5 世界主持能力。

### 当前不做

不建立 Beat graph、precondition DSL、branch tree、剧情收敛状态机、PROLOGUE_SCENARIO_MODE。

### Revisit trigger

- G5 World Initiative 已成立后，真实作者需要 authored prologue；
- Owner 先完成至少一份真实 Opening Scenario 创作实验，再决定 machine representation。

---

## 6. Player-known Entity Directory / Long-lived Dossier

### 价值

历史裁定已经明确：

```text
Current Scene Visible Characters
!=
Player-known Character Directory
```

玩家认识过的人物应跨场景长期保留，但只显示玩家合法知道的信息；同理 Knowledge / Objective 等长期 Surface 最终需要分类、筛选、搜索与历史分层。

### 当前不做

G4 Source character / game-local character 不自动进入 People UI；完整 Directory owner 与 UI 留给 G5 Knowledge Provenance / G6 RPG Experience。

### Revisit trigger

玩家实际认识多个离场人物后，当前三栏 UI 已无法可靠表达“认识过谁 / 最后知道什么”。

---

## 7. Reference Library / Large Lore Retrieval

### 价值

大型历史、制度、地理、文化、技术和研究资料不适合无限塞进 World Pack；资料库作为可复用参考资源层有长期价值。

Canonical historical lesson：

```text
Library bound
!= Runtime relevant
!= Player known
!= Model visible
```

### 当前不做

不建设 RAG/vector database、资料库管理 UI、自动语义检索、Reference Provider 或 Library external protocol。

### Revisit trigger

- 两个以上真实 World Pack 出现大量重复参考资料；
- G7 长上下文验证证明人工/静态 Source slicing 不足；
- Creator 真实创作过程需要按需研究资料。

---

## 8. Asset Family / Bundle / Version Lock

### 价值

旧资产仓库用 Asset Family 聚合一部作品使用的 World / Character / Expansion，并以 Bundle 表达某次交付的版本锁。对长期内容生产和发行有价值。

### 当前不做

G4 先证明两个 Pack 的本地独立建局，不构造通用 Bundle manager、dependency resolver 或作品发行协议。

### Revisit trigger

一个真实 World Pack 开始依赖多个独立 Character / Expansion / Library，并且需要可重复安装同一组合。

---

## 9. Conversational Creator / AI-assisted Authoring

### 价值

历史上形成的成熟方向：

```text
Structured Creator Workspace
+
AI Authoring Conversation
→ typed Draft edits
→ deterministic Validator
→ visible change set / Undo
→ user Save / Publish
```

AI 可以编辑 Draft，但不能静默发布 Source Asset；Conversation 不是资产事实源；无 Provider 时 Creator 仍应可手工使用。

### 当前不做

G4 不建设 Creator 产品，不把 prompt/chat/model metadata 塞进 World Pack schema。

### Revisit trigger

G8 Authoring 开始前，先让 Owner 用最小 prototype 真实创作一个 World Pack / Entry，复盘字段负担后再冻结 Creator UX。

---

## 10. Gameplay Map System

### 价值

长期可能需要 Region / Place / Scene、道路/水路、可达连接、旅行时间、地图标记、势力范围与玩家已知地图投影。

### 当前处理

G4 只支持 authored map asset/source reference + Asset Resolution。

### 当前不做

不建立 topology graph、寻路、旅行 simulator、战术地图、地图编辑器或 procedural geography platform。

### Revisit trigger

真实游戏已经产生持续的地理移动与位置维护需求，仅靠 Narrative + authored map 图片无法支撑理解/决策。

---

## 11. Battle / Mechanic Dedicated Surfaces

### 价值

战斗、经营、政治、系统商城等高频机制最终可能需要专门 UI，而不是全部塞进 Narrative。

### 当前不做

不因为 G4 有 World Surface Host 就提前建设战斗面板、骰点控制台、政治仪表盘等。

### Revisit trigger

G5 某机制在连续 Owner UAT 中高频出现，并且文本交互明显降低理解/操作效率。

---

## 12. Advanced Save / Timeline Product Surfaces

候选包括：

- Timeline browser；
- arbitrary per-turn rewind；
- backup browser；
- branch picker；
- revision history；
- 更丰富的 Save manager。

G3 已证明底层 Recovery/branch/backups，但第一代产品刻意不把内部调试历史全部暴露给玩家。

### Revisit trigger

长局 Owner UAT 反复证明 named Save + recent Recovery 不足以纠正常见错误，且新增 UI 的认知成本明显低于恢复收益。

---

## 13. Online Pack Store / Cloud / Account

### 价值

长期可能需要 Pack 分享、更新、云存档、跨设备、作者发布与市场。

### 当前不做

第一代坚持 local-first / single-player-first，不引入账号、服务器、在线商店、远程代码包或云同步复杂度。

### Revisit trigger

Standalone Alpha 已长期稳定，且真实用户/发行需求出现。

---

## 14. Autonomous Creator Agent / Cross-asset Operations / Auto Research

候选包括：

- 跨多个资产批量重构；
- 长时间 autonomous authoring agent；
- 自动联网研究；
- 通用任务调度器；
- speculative vector/RAG platform。

### 当前不做

这些能力在旧项目中已明确属于 deferred optional，不是 Creator 首版条件。

### Revisit trigger

基础 Creator 经过真实 UAT 后，有明确重复劳动和高价值自动化需求，并且简单 typed tools 无法解决。

---

## 15. 重新进入 Roadmap 的检查表

任何候选要进入 CURRENT 前，至少回答：

```text
1. 当前真实玩家/作者遇到了什么问题？
2. 不做它的实际损失是什么？
3. 是否已有更简单能力能解决？
4. 是否有第二个真实消费者，还是只为未来想象？
5. 它会不会压缩 AI GM 的自然创作空间？
6. 普通错误是否可以用 Retry / Save / Recovery 更便宜地处理？
7. 是否会制造新的第二事实源、万能协议或框架森林？
8. 最小可试玩 vertical 是什么？
9. Owner UAT 如何判断它真的更好？
```

通过后，先更新 CURRENT Roadmap / Architecture，再创建 Task Packet；不能反过来先实现再找理由。
