# 大型场景建模工作流

状态：current

## 1. 问题定义

大型建筑群、城市、宫殿、园区等复杂 3D 场景，如果直接让 Agent 从少量参考图出发一次性完成：

- 理解需求；
- 总体规划；
- 单体建筑设计；
- Blender 建模；
- 地形与景观；
- 渲染；
- QA；

Agent 往往会优先保证“场景完整、脚本可运行、验收清单能勾选”，而牺牲设计图忠实度和单体质量。

常见表现：

- 大量建筑由少数模板重复生成；
- 建筑数量很多，但真正独立设计的建筑很少；
- 总平面被 Agent 为了程序便利重新规则化；
- 局部院落、道路、水岸和墙线被简化；
- 直到最终渲染才发现总体布局已经偏离参考设计。

因此大型场景应采用**分层设计、阶段冻结、逐级装配**。

---

## 2. 推荐四级空间分解

### Level 1：单体资产

优先把高价值建筑单独做好，例如：

- 主殿；
- 宫门；
- 寝殿；
- 官署；
- 角楼；
- 长廊；
- 亭；
- 桥；
- 高阁；
- 佛塔。

每个单体都应经历：

```text
设计
→ 建模
→ 单体渲染
→ 独立审核
→ Owner 审核
→ Asset Freeze
```

### Level 2：院落 / 空间模块

验证：

```text
主建筑
+ 配殿
+ 宫门
+ 院墙
+ 回廊
+ 庭院
```

重点不是再做大量建筑，而是检查建筑间比例、间距、视线和入口关系。

### Level 3：宫区 / 街区

将已批准的单体与院落组合成更大的功能区，例如：

- 外朝；
- 内廷；
- 文官区；
- 武官区；
- 园林区；
- 宴会区。

### Level 4：总场景装配

这一阶段 Agent 原则上不再重新设计核心建筑，只负责：

- 调用已批准资产；
- 按冻结后的 Masterplan 定位；
- 做必要的局部适配；
- 完成整体地形、景观与渲染整合。

## 3. 推荐完整 Pipeline

```text
需求定义
↓
概念设计
↓
总体设计图
↓
分区局部设计图
↓
Digital Masterplan
↓
Footprint / Whitebox
↓
总平面 Review
↓
Masterplan Freeze
↓
单体 Asset
↓
Asset Review / Freeze
↓
院落模块
↓
宫区 / 街区
↓
总场景装配
↓
地形 / 水系 / 景观深化
↓
QA
↓
最终设计审核
↓
目标平台转译
```

## 4. 为什么要先 Whitebox

Whitebox 阶段只允许建立：

- 地形；
- 水域；
- 墙；
- 门；
- 道路；
- 桥；
- 建筑 footprint proxy。

建筑只需要低矮色块，不建立屋顶、柱网、斗拱、门窗等正式结构。

这一阶段的唯一问题是：

> **总平面是否忠实、比例是否成立、交通是否连通？**

若 Whitebox 没有 PASS，继续正式建模只会增加沉没成本。

---

## 5. Prototype 与 Production Model 必须区分

复杂 Agent 建模的第一批成果往往更适合作为：

- Massing Prototype；
- Whitebox；
- Parametric Prototype；

而不是最终 Production Model。

白模的价值是验证：

- 尺度；
- 空间组织；
- 交通；
- 参数化能力；
- Blender Python 是否可支撑该规模。

不要因为白模粗糙就误判技术路线失败，也不要把白模直接通过“继续加细节”硬升级成最终资产。若底层设计与模块体系不成熟，应该回到上游重构。
