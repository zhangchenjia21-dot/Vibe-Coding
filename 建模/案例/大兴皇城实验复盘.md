# 大兴皇城实验复盘

状态：current case study  
日期：2026-09-08

## 1. 实验目标

目标是先设计一座架空东方帝国皇宫，再让 Agent 使用 Blender 程序化建模，为未来 Minecraft 大型皇宫建设提供预想设计参考。

设计方向：

- 中国传统宫殿为主体语言；
- 明制秩序骨架；
- 唐风恢弘体量；
- 宋式园林气质；
- 中等幻想强化；
- 帝国级尺度；
- 强中轴、外围自由展开；
- 多层宫墙；
- 大型后宫；
- 皇家藏书高阁与后苑佛塔作为两大奇观节点。

最初形成了三张主要设计图：

1. 皇宫总平面设计图；
2. 皇宫建筑建模蓝图；
3. 宫门表与交通连接关系图。

随后将完全相同的任务和图片分别交给 Codex 与 Kimi 并行完成 Blender 建模，构成 A/B Test。

---

## 2. 第一轮完整建模的结果

两种 Agent 都能生成完整宫城场景，包含：

- 宫墙；
- G01–G10 宫门；
- 道路；
- 主殿；
- 内廷；
- 文武官区；
- 水系；
- 御苑；
- 藏书高阁；
- 佛塔；
- 地形；
- 多视角渲染；
- Python 脚本和报告。

但都出现明显问题：

### A. 单体建筑粗糙 / 同质化

大量建筑由少量通用生成器和 compound 模板批量生成。

结果表现为：

> 对象很多，但真正独立完成的建筑设计很少。

### B. 设计图只被“语义理解”，没有被几何忠实复现

Agent 都理解了：

- 东文西武；
- 中央主殿；
- 北部御苑；
- 后宫；
- 水院；
- 佛塔。

但它们各自重新建立了一套尺寸和坐标。

例如同一参考设计下，Codex 与 Kimi 采用了明显不同的：

- 皇宫总长宽；
- 大朝会殿尺寸；
- 佛塔高度；
- 藏书高阁高度；
- 各宫区位置参数。

这证明复杂 PNG 输入没有自然变成统一几何事实源。

## 3. Codex 与 Kimi A/B Test

输入条件保持一致：

- 相同任务文本；
- 相同三张设计图；
- 相同最终目标。

### Codex 表现

优势：

- 综合视觉完成度更高；
- 材质、屋顶、园林、水院、场景密度更成熟；
- Collection 和脚本工程组织较好；
- 几何 QA 较认真；
- 对门洞、道路、桥梁、通行进行了实际验证。

不足：

- 仍然自行重新参数化总平面；
- 建筑模板化明显；
- 与设计图主要是语义一致，不是严格几何一致。

### Kimi 表现

优势：

- 代码职责拆分清楚；
- 使用 `plan.py` 集中管理布局数据的思想值得吸收；
- 参数化结构清楚。

不足：

- 最终单体视觉明显更粗；
- 建筑重复感更强；
- 同样自行定义了一套“唯一事实源”，但该事实源并不是从设计图严格数字化而来。

### A/B 结论

在此次相同的大型 Blender 建模任务下：

> **Codex 的综合建模结果明显优于 Kimi。**

但更重要的结论是：

> **两者都会自主重构设计，因此换 Agent 不能从根本上解决“忠实还原”问题。**

主要瓶颈来自：

- 任务跨度过大；
- 设计资料不是机器可执行几何；
- 缺少中间 Stage Gate；
- 单体资产没有先冻结。

---

## 4. 宫门与宫墙经验

第一版设计图对宫门标注不足，存在 Agent 漏门、墙体封路的风险。

修订后增加：

- G01–G10 明确宫门编号；
- 宫门表；
- 主轴与二级道路；
- 桥梁 / 园路连接。

结果表明：

> 明确的交通拓扑可以显著改善 Agent 的连通性实现。

但同时发现：

> Topology 正确不代表 Geometry 忠实。

Agent 可以做到“G01 能走到 G10”，但门的位置、道路宽度、宫区边界仍可能与原图不同。

宫墙设计也得到一个原则：

> 每一道墙都必须能够回答“它分隔什么、控制什么通行、为什么存在”。

不能为了满足“多重宫墙”要求而无意义重复堆墙。

---

## 5. 后宫规模修正

早期总图中的内廷 / 后宫明显偏小，与文武官区不匹配。

修订目标：

- 后宫成为大型独立宫区；
- 规模至少接近单侧文官 / 武官区；
- 中央帝后寝宫 + 东西附属宫院；
- 多进庭院；
- 独立内廷宫墙；
- 与御苑正式连接。

这一修订说明：

> 大型空间的“功能存在”不够，还必须明确其相对量级和视觉权重。

---

## 6. 总图分辨率问题

后续 Codex 在数字化总平面时，将总图按区域裁切并叠加像素网格。

发现：

- 整体宫城图约 1491 × 1055；
- 宏观关系清楚；
- 文官区、武官区、内廷、水院、后苑等高密度区域一旦放大就明显模糊；
- 小建筑 footprint、墙线、门洞、回廊、水岸难以准确判断。

因此确认：

> **大型总图必须配套专门重新设计的高分辨率局部图。**

不是简单裁剪放大，因为放大已有像素不会产生新信息。

推荐至少三层设计资料：

```text
L0 总体图
→ 轴线 / 分区 / 总体边界

L1 分区局部图
→ 宫区 / 街区具体组织

L2 单体 / 院落图
→ 资产本身的平立剖与尺寸
```

## 7. 工作流修正

实验后不再推荐：

```text
概念图
→ 超级 Prompt
→ 整座宫城成品
```

改为：

```text
需求
↓
概念设计
↓
总图
↓
高分辨率局部图
↓
Digital Masterplan
↓
Footprint / Whitebox
↓
总平面审核与 Freeze
↓
高质量单体资产
↓
院落模块
↓
宫区
↓
总装
↓
景观深化
↓
QA
↓
目标平台转译
```

## 8. 两批完整皇宫成果的正确定位

不应把它们定义为失败的 Production Model。

更准确地说：

- Codex：**大兴皇城参数化总体原型 A**；
- Kimi：**大兴皇城参数化总体原型 B**。

它们验证了：

- Blender Python 可支撑城市级场景；
- 复杂宫城可以参数化生成；
- 多层宫墙和交通系统可以实现；
- 大型场景需要更严格的设计数据和 Stage Gate。

它们的主要价值是验证 Pipeline，而不是成为最终建筑资产。

---

## 9. 下一步建议

不继续在当前两批完整皇宫上无脑加细节。

优先做两个实验：

### 实验 A：Masterplan Reconstruction

禁止正式建筑，只做：

- 地形；
- 水系；
- 宫墙；
- 门；
- 道路；
- 桥梁；
- footprint proxy。

验证 Agent 能否忠实复现总体设计。

### 实验 B：Hero Asset

选择一栋核心建筑（例如大朝会殿）：

- 单独设计；
- 单独建模；
- 单独审核；
- 冻结为高质量资产。

两个实验分别验证：

> **“布局能否忠实”** 与 **“单体能否高质量”**。

只有两者都通过，才值得重新进入整座皇城装配。
