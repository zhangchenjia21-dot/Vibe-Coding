# 建筑资产模块化与复用

状态：current

## 1. 核心原则

大型建筑群的质量上限，首先取决于单体资产质量，而不是场景里有多少对象。

如果 Agent 在一次任务里同时承担数十到数百栋建筑，它通常会创建：

- 一个通用大殿生成器；
- 一个通用院落生成器；
- 少量屋顶 / 墙 / 柱模板；
- 大量位置和尺寸变体。

这可以快速形成完整场景，但容易导致：

> **建筑数量很多，真正独立完成的设计很少。**

因此高质量建筑应先资产化，再进入大型场景装配。

---

## 2. 推荐资产层级

### L1：最高等级 / 核心地标

例如：

- 帝国正门；
- 核心主殿；
- 大型高阁；
- 佛塔 / 圣塔。

要求独立设计、独立审核，不能只是通用模板放大。

### L2：重要皇家 / 公共建筑

例如：

- 次级大殿；
- 寝宫；
- 宴会殿；
- 重要门楼。

### L3：宫区 / 街区主要建筑

例如：

- 官署；
- 附属寝殿；
- 标准厅堂。

### L4：附属构件 / 小型建筑

例如：

- 配殿；
- 门房；
- 长廊；
- 亭；
- 小桥。

等级应通过尺寸、台基、屋顶形式、材质、构件复杂度体现。

---

## 3. 单体资产的正确流程

每个重要资产建议经历：

```text
需求 / 风格定义
↓
参考图 / 平面 / 立面
↓
单体建模
↓
多角度渲染
↓
设计审核
↓
工程审核
↓
Owner PASS
↓
Asset Freeze
```

冻结后再进入资产库。

资产命名应稳定、可检索、可版本化，例如：

```text
ASSET_L1_GREAT_AUDIENCE_HALL_V1
ASSET_GATE_MAJOR_V2
ASSET_CORRIDOR_STANDARD_V1
```

不要长期使用：

```text
final
final2
latest
new
```

---

## 4. 院落也是资产

“模块化”不应只理解为单栋楼。

很多建筑群真正可复用的单元是：

```text
主殿
+ 东西配殿
+ 门
+ 院墙
+ 回廊
+ 庭院
```

因此可建立两级资产库：

### Building Asset Library

单栋建筑。

### Spatial Module Library

完整院落、街坊、庭院、桥水组合等空间模块。

这样总场景装配时不必每次重新推断所有间距与关系。

---

## 5. 程序化生成器的正确定位

程序化生成器非常适合：

- 批量次级资产；
- 参数化尺寸；
- 重复柱列；
- 标准化台基；
- 屋顶构件；
- 长廊；
- 宫墙；
- 植被代理。

但它不应自动承担所有核心建筑的设计。

建议区分：

```text
Hero Asset
→ 独立设计

Standard Asset
→ 参数化模板 + 明确变体

Filler Asset
→ 允许批量程序生成
```

不要用 Filler Asset 的生产方式处理核心奇观。

---

## 6. 总装阶段的约束

当资产和 Masterplan 均已冻结后，总装 Agent 的职责应收窄为：

- 加载资产；
- 按 ID 和坐标定位；
- 处理必要接口；
- 统一材质 / 光照；
- 景观整合；
- QA。

不得在总装阶段：

- 临时重新设计主殿；
- 擅自替换重要资产；
- 改变总平面；
- 为了代码方便把复杂建筑群变成重复阵列。

---

## 7. 与 Minecraft 等目标平台的关系

设计资产不必从一开始就被方块网格限制。

推荐：

```text
Blender Design Asset
↓
Owner Approved Asset
↓
Platform Translation Spec
↓
Minecraft / 游戏 / 其它目标平台实现
```

设计模型负责：

- 造型；
- 比例；
- 空间；
- 天际线；
- 视觉关系。

目标平台转译再处理：

- 方块化；
- 网格化；
- 材质替换；
- LOD；
- 性能与施工约束。

核心原则：**高质量资产一旦批准，应复用，而不是每次让 Agent 从零重新发明。**
