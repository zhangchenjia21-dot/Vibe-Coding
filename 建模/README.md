# 建模

状态：current  
建立日期：2026-09-08

本目录沉淀 AI 辅助 3D / 建筑场景建模中的跨项目经验，重点覆盖：概念设计到数字总平面、复杂场景拆分、单体资产模块化、Blender Agent 派工、Stage Gate、QA 与独立验收。

这里记录的是可复用的方法论和经验证据，不保存具体项目的运行事实。具体 `.blend`、脚本、渲染、测试和构建事实应继续留在对应实现项目；经过多次验证、已经形成稳定可重复执行流程的方法，可进一步晋升到 `skill/`。

## 当前核心结论

1. **大型场景不要一 Prompt 到底。** 需求理解、总规划、单体设计、建模、景观、验证不应全部压进同一 Agent 任务。
2. **先总平面，后建筑。** 正式建筑建模前先完成 Digital Masterplan 与 Footprint / Whitebox 验证。
3. **先单体，后院落；先院落，后宫区；最后才总装。** 大规模重复实例不能替代真正的建筑设计。
4. **概念 PNG 不是施工蓝图。** “看起来像蓝图”的位图不能替代明确的坐标、轮廓和尺寸数据。
5. **拓扑正确不等于几何正确。** 门和道路“能连通”不代表位置、比例和边界忠实于设计。
6. **大型总图必须配套高分辨率局部设计图。** 放大总图不会产生新的细节信息。
7. **需要忠实复现时必须建立 Digital Masterplan。** JSON / SVG 等结构化数据应成为后续施工的几何事实源。
8. **正式建模前必须设置 Footprint / Whitebox Stage Gate。** 总平面未 PASS，不继续堆建筑细节。
9. **Builder 的 PASS 不是独立验收。** 报告、manifest、完成声明需要由实际 `.blend`、渲染、脚本和几何检查验证。
10. **高质量建筑应资产化、版本化、复用。** 不要在每个大型场景中重新让 Agent 发明同一类建筑。

## 推荐的大型 AI 建模 Pipeline

```text
需求定义
↓
概念设计
↓
总体设计图
↓
分区局部设计图
↓
数字化 Masterplan
↓
Masterplan / Footprint 白模
↓
Owner / Independent Review
↓
Masterplan Freeze
↓
单体建筑设计
↓
单体 Blender Asset
↓
Asset Review / Freeze
↓
标准院落 / 空间模块
↓
宫区 / 街区组合
↓
大型场景总装
↓
地形 / 水系 / 景观深化
↓
Blender QA
↓
最终设计审核
↓
目标平台转译（如 Minecraft）
↓
施工 / 实现
```

核心原则：**上游几何一旦冻结，下游 Agent 不得静默重新设计。**
