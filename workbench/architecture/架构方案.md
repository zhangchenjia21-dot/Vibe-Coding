# 1. Architecture Goal

当前产品：

```text
Personal State / Information & Action Desktop

CORE
├─ Today
├─ Plan
└─ Tracks

V0
= Thin Tracks + Usable Plan + Derived Today
```

架构目标：

> Workbench 自己可靠拥有 Core Personal State；Tracks / Plan 保存长期与未来事实，Today 只按当前日期派生需要展示的信息，并保留极窄的当天确认状态；桌面宿主与本地持久化足够支持长期驻留、频繁唤起和真实个人数据长期演化。

# 3. Canonical Ownership

## 3.1 Tracks

Tracks 是长期事项真实状态的 authoritative owner。

至少拥有：

```text
TrackStableID
Name
Long-term Goal
Current Phase
Current Real State
Near-term Direction
Last Updated
Status: Active / Completed / Archived
```

约束：

- `TrackStableID` 为不可变内部身份；
- `Name` 可编辑，不承担 identity；
- Plan 对 Track 的关联引用 stable ID；
- Track 改名不得破坏 Plan linkage；
- Milestones / Sources / AI update 不因未来可能性进入 V0 platform。

## 3.2 Plan

Plan 是未来安排与注意力配置的 authoritative owner。

V0 业务语义包括：

- 单次 Scheduled Item；
- Recurring Series；
- Recurrence Exception；
- Unscheduled；
- Reminder；
- Memo；
- Current Vector；
- 可选 Track Link。

用户模型上保持这些语义清晰，不强迫它们通过一个“万能事项”表单呈现。底层可复用字段不改变用户语义边界。

## 3.3 Today

Today 是按 Owner 本地当前日期计算的 derived view。

Today 读取：

- Current Vector；
- 当天单次日程；
- 当天循环 occurrence；
- 今日 Reminder；
- 今日 Memo。

Today 不复制 Plan / Track 的业务事实。

唯一可持久化辅助状态是极窄的 Today Acknowledgement：

```text
LocalDisplayDate
+
StableSourceIdentity / OccurrenceIdentity
+
Acknowledged
```

该状态只用于当天“已完成”的视觉确认：

- 不修改 Plan；
- 不修改 Track；
- 不修改 recurring series；
- 不产生完成率、streak 或评分；
- 当天重启后应恢复；
- V0 不建设长期行为历史 / 统计产品。

# 4. Identity Contract

所有需要被长期引用的对象必须有稳定内部身份；显示名称、标题和当前时间均不能替代 identity。

## Track

```text
TrackIdentity = immutable internal ID
```

## 普通单次对象

Scheduled Item / Reminder / Memo / Unscheduled / Vector 使用自己的 immutable internal ID。

## Recurring Series

```text
SeriesIdentity = immutable Series ID
```

## Occurrence

```text
OccurrenceIdentity
=
SeriesStableID
+
OriginalScheduledOccurrenceKey
```

`OriginalScheduledOccurrenceKey` 表示该 occurrence 在原 series 规则下本来应该发生的本地日期 / 时间位置。

若某 occurrence 从周一 09:00 单次移动到周二 15:00，其身份仍指向原本周一 09:00 的 occurrence，不改用新的显示开始时间。

该 identity 同时供：

- 单次 edit exception；
- 单次 delete exception；
- Today projection；
- Today acknowledgement。

# 5. Date / Time Contract

## 5.1 Date-only

纯日期是日历日期，不等同于 timestamp / UTC midnight。

用于：

- Current Vector start / end date；
- date-only Reminder；
- Memo display date；
- 日历日期；
- recurrence local calendar date。

禁止通过 `00:00 UTC` 偷偷表示 date-only。

## 5.2 Local time

Owner 在 Calendar 中表达的“每天 / 每周当地 09:00”使用 local wall-time semantics。

DST 或系统时区 offset 变化时，日程仍以用户理解的本地 09:00 为语义目标，不固定为某个 UTC hour。

## 5.3 Instant / timestamp

真正的时间戳只用于需要记录绝对时间点的系统事实，例如：

- created_at；
- updated_at；
- backup created time；
- migration / diagnostic metadata。

## 5.4 Current Vector

Current Vector 日期区间采用两端包含：

```text
[startDate, endDate]
```

同一天最多一个 Vector；任何新建 / 编辑导致日期重叠时拒绝保存，由 Owner 自己调整，Workbench 不自动截断其它 Vector。

# 6. Recurrence Contract

V0 recurrence：

```text
Series Definition
→ Dynamic Occurrence Expansion
→ Persisted Exception only when needed
```

不预先持久化整个未来 occurrence 列表。

支持：

- 每天；
- 每周指定星期；
- start date；
- optional end date；
- local start / end time；
- optional Track Link。

Occurrence edit / delete 的 V0 作用范围只允许：

```text
仅这一次
整个循环
```

明确不做：

```text
这一次及以后
```

单次修改 / 删除只产生 exception，不改其它 occurrence。

Whole-series edit 若已有 exceptions，执行第 2 节 RC-04 policy：警告后清空旧 exceptions，不自动 remap。

# 7. Persistence Contract

## 7.1 Canonical Store

**Electron + SQLite** 是当前 G0.5 Architecture Candidate。

V0 Core Personal State 的唯一 canonical persistent store：

> 一个本地 SQLite application database。

正式 DB 放在 Windows per-user application data location，不放在：

- 安装目录；
- GitHub / implementation repository；
- 项目代码 checkout；
- 被产品逻辑默认假定的云同步目录。

具体 SQLite runtime binding / library 留给 implementation task 在不改变本合同前提下选择。

## 7.2 Durability

- canonical writes 使用 transaction；
- 已 commit 的状态在异常退出 / restart 后必须恢复；
- 未 commit 的半写入不得成为 canonical state；
- migration 使用 transaction 并支持失败 rollback。

## 7.3 Schema Version / Migration

从 V0 开始保留：

```text
schema version
+
ordered transactional migrations
+
migration fixture / rollback tests
```

真实 Owner 数据进入系统后，不允许通过“删库重建”替代正常升级路径。

软件启动发现旧 schema 时：

```text
创建升级前 safety backup
→ 执行 transaction migration
→ integrity / expected-version validation
→ 成功后正常启动
```

升级失败必须回滚并停止使用半升级 canonical DB。

# 8. Backup / Restore Contract

## Manual Backup

Workbench 使用 SQLite consistent snapshot / backup operation 生成一个独立、可验证的 backup file。

V0 不建设：

- cloud backup；
- multi-device sync；
- 自动版本历史系统。

## Restore

```text
选择 backup
→ 验证是合法 Workbench DB
→ integrity check
→ 读取 schema version
→ 确认存在 migration path
→ 自动创建当前 live DB safety snapshot
→ 在 staging 位置准备 / 必要时迁移 backup
→ 再次验证
→ 关闭 canonical DB connection
→ 替换 canonical DB
→ reopen / verify
```

禁止把任意用户选择文件直接覆盖 canonical DB。

Restore 前 safety snapshot 与升级前 safety backup 都属于 V0 低成本 recovery guardrail。

# 9. Desktop Host Contract

## V0 Host

**Electron = G0.5 selected Desktop Host candidate。**

原因：

- G0.4 已证明 Windows packaged tray lifecycle 可行；
- 与 Tauri 相比减少 Rust + WebView2 / Wry 等额外工程链；
- 对 AI 主导、快速迭代的个人应用，降低技术栈与调试复杂度优先于更小安装包 / 内存优势；
- 当前 UI 形态天然适合 Web-style desktop rendering。

Tauri 不作为同时维护的第二 host；只有未来出现真实资源 / 分发问题时才重新评估。

## V0 Desktop behavior

- 正常启动默认进入 Today；
- system tray 为 V0 Required；
- 点击窗口关闭按钮默认隐藏到 tray，不退出进程；
- tray 图标可以恢复 / focus 主窗口；
- tray menu 提供真正退出；
- 开机启动 Deferred。

## Route Freeze residual check

G0.6 前在 Owner 实际 Windows 工作站做 focused check：

```text
launch
→ notification-area icon 可见
→ 真实鼠标点击恢复 / focus
→ close → hide to tray
→ tray real exit
```

该检查不需要产品业务 UI，也不属于新大型 Spike。

# 10. UI / IA Boundary

## Today

默认保持窄：

- Current Vector；
- Today's Schedule；
- 今日 Reminder；
- 今日 Memo。

不默认显示：

- 全部 Tracks；
- Unscheduled；
- 未来预告；
- 完成率 / streak / score。

## Plan

- Calendar 是主要时间视图；
- Unscheduled / Reminder / Memo / Vector 保持清晰独立入口；
- 不冻结左右栏 / drawer / modal 等具体组件布局；
- 不用一个万能表单抹平不同对象语义。

## Tracks

默认 Active；Completed / Archived 独立入口。

Thin Track 字段边界由 First Usable Owner UAT 验证，Milestones 继续 Deferred。
