## 0. 状态语义

所有架构判断只使用以下三种决策状态：

- **DECIDED**：已有足够 current evidence，可作为当前约束；若未来新证据冲突，仍需走 Decision Propagation。
- **HYPOTHESIS**：工作假设 / open question；不得作为 implementation commitment，必须由 Product / Reference / Spike / Owner 继续验证。
- **DEFERRED**：现在决定会形成 speculative architecture，明确延后到 revisit trigger 出现。

问题分类：

- **A. Product-dependent**：取决于 Product Definition 或 Owner 进一步裁定。
- **B. Reference-dependent**：必须由 02 Reference Audit / 外部 current evidence 先回答。
- **C. Spike-required**：文档不足，必须用低成本真实技术实验回答。
- **D. Can decide now**：已有足够 current evidence，可先确定低风险约束。
- **E. Must defer**：当前没有真实 consumer / requirement，提前决定会制造无效沉没成本。

# A. Product-dependent

## AQ-A01｜Windows-only 是否是 V0 Hard Constraint？

- **Question**：V0 是否只承诺 Owner 当前 Windows 工作站，还是要求技术路线从第一天就具备跨平台可迁移性？

- **Category**：Product-dependent
- **Downstream impact**：TV-01、TV-04、packaging、process supervisor、framework selection。
- **Cost of being wrong**：**HIGH**。若先按跨平台设计后才确认 Windows-only，会增加无价值抽象；反之若绑定 Windows 专属能力后又要求跨平台，会造成 host/runtime 重构。
- **Required evidence**：Owner 对 V0 deployment target 的明确裁定；02 可提供候选路线跨平台成本，但不能替 Owner 决定产品承诺。
- **Current hypothesis**：V0 以 Owner 当前 Windows 环境作为第一现实目标，但是否升级为正式 Hard Constraint 尚未裁定。
- **Decision status**：**HYPOTHESIS**
- **Owner / next destination**：00 + Owner；03 在 G0.5 收敛。

# G. Candidate State Model Questions

Product Definition 已要求至少能够理解以下用户流程状态，但**列出状态不等于冻结最终 schema**：

```text
Draft / Ready to Run
Running
Completed
Failed
Git Pending
Ready for Review
Review Requested
Reviewed
Rework Needed
Accepted
```

当前必须继续回答：

6. crash/restart 后是否增加 `Interrupted / Unknown / Reconciling`，还是内部 reconciliation 不暴露给 Owner？

- Product Core Loop：`Discuss → Select → Execute → Push → Review → Fix / Accept`。
- Codex-first vertical；其它 Agent 不阻塞 V0。
- Selected Text 定义 execution intent；不要求 GPT 特殊 Task schema。
