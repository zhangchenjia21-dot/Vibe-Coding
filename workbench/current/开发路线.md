# 1. Route Inputs

当前正式产品方向：

```text
Personal State / Information & Action Desktop

CORE
├─ Today
├─ Plan
└─ Tracks

V0
= Thin Tracks + Usable Plan + Derived Today
```

核心产品关系：

```text
Tracks
长期事项与当前真实状态
        ↓ 可选关联
Plan
未来安排 / 日程 / Reminder / Memo / Current Vector / Unscheduled
        ↓ 按当前日期派生
Today
默认首页 / 当日信息切片
```

当前实现策略倾向：

> **架构阶段先把高返工风险收敛；Route Freeze 后不人为把小型 V0 拆成很多产品阶段，优先集中实现完整 V0，再让 Owner 用真实数据一次性做首轮 UAT。**

这不意味着跳过工程验证：实现阶段内部仍需要 deterministic tests / integration gates；只是这些不拆成多个必须等待 Owner 逐阶段试玩的产品 Stage。

# 2. 已经 Owner 认可、路线必须保护的约束

1. Workbench 自己拥有 Core Personal State；
2. Today 主要是 derived view，不建立 Plan / Tracks 的第二份 live truth；
3. Today 的“已完成”只是当天视觉确认，不改变 Plan / Track，不做完成率 / streak / 评分；
4. Today 当日确认在重启后应保留，但 V0 不建设长期完成历史系统；
5. Current Vector 同一天最多一个，日期区间禁止重叠，Workbench 不自动截断其它 Vector；
6. 循环事项保存 series definition，occurrence 按日期动态派生；单次修改 / 删除只保存 exception；
7. 循环编辑 / 删除 V0 只提供“仅这一次 / 整个循环”，不做“这一次及以后”；
8. 核心数据本地保存；V0 需要可靠 restart、手动 backup / restore、可升级 migration；
9. 系统托盘是 V0 Required；关闭窗口默认隐藏到托盘，托盘可恢复 / 真正退出；开机启动后续增加；
10. Today 默认只聚焦 Current Vector / 今日 Schedule / 今日 Reminder / 今日 Memo；
11. Plan 允许日程、Unscheduled、Reminder、Memo、Vector 各自保持清晰用户语义，不强制万能表单；
12. Tracks 保持 Thin，不因未来 AI / Source / Milestone 提前平台化；
13. Sources / Update Mode 可预留最小语义空间，但 V0 UI 不展示、不实现同步 / AI update platform；
14. Milestones、GitHub sync、AI Track Update、Google Calendar、Launch Target、Custom Functions、Knowledge / Habit / Finance / Health、Plugin / SDK / Page Builder、AI Collaboration 均不阻塞 V0。

详细问题与开放实现点见：[`../architecture/架构问题登记表.md`](../architecture/架构问题登记表.md)。

# 5. Reference Audit Handoff to 02

02 的任务是**攻击这条路线**，不是帮它找支持材料。

## 5.1 最脆弱的假设

1. Today 可以保持主要派生，只增加极窄当天 acknowledgement，而不会形成第二 truth；
2. “动态 occurrence + exception”足够覆盖 V0 recurrence，且不需要“这次及以后”；
3. 当前 V0 一次集中实现后再做首次 Owner UAT，沉没成本仍可接受；
4. 月 / 周 Calendar + Reminder / Memo / Unscheduled / Vector 可以在不演化成完整 Todo/Calendar suite 的前提下保持简单；
5. Track 的 thin model 足以承载真实 CPA / 求职 / 项目状态；
6. 系统托盘 + Today 默认入口足以形成长期驻留感，开机启动可以后置；
7. 本地单一 canonical store + 手动 backup/restore 足以满足 V0 数据安全；
8. Sources / Update Mode 不展示、不建平台不会阻塞未来扩展；
9. Plan 类型保持不同 UX 语义不会导致底层模型无法维护；
10. V0 不需要同步也能产生足够日常价值。

## 5.2 值得研究的外部参考类型

不要做产品大全，按 seam 选样本：

- Calendar / recurrence：Google Calendar、Outlook Calendar、Apple Calendar 等成熟 recurrence semantics；
- Personal planner：Todoist、TickTick、Things、Morgen、Akiflow、Sunsama、Routine、Amie 等候选（以 current reality 为准）；
- Today / daily dashboard：研究如何控制首页信息密度、empty state 与完成反馈；
- Long-term track / project state：Notion / Linear / project dashboard 类产品如何表达“当前真实状态”而非百分比；
- Windows desktop shell：Electron / Tauri / Native / Web-local host 的 current tray / packaging / lifecycle 能力。

研究目标：

```text
哪些 domain semantics 经长期验证
哪些 UI 只是漂亮但维护成本高
哪些系统把 Home/Today 做成第二 truth
哪些 recurrence edge case 反复导致返工
哪些 desktop framework 在 Windows tray / persistence / packaging 上存在真实限制
```

## 5.3 值得回溯的历史经验

- 当前 Pivot Discovery：`workbench/discussion/产品方向评审.md`；
- lifecycle-dev-process 中关于 canonical ownership / persistence / first consumer / late UAT 的经验；
- 旧 Workbench 路线只回溯“过早 platform / 外部依赖 / Owner UAT 太晚”的经验，不复用旧架构；
- 用户其它项目中真实 persistence / migration / desktop packaging / UAT 返工记录，如有直接证据再定向读取。

## 5.4 需要 technical spike 而不是只查网页的问题

- tray hide / restore / exit 的真实 packaged Windows behavior；
- host 关闭 / crash 后 local store durability；
- backup / restore round-trip；
- schema migration from old fixture；
- recurrence series → occurrence → exception；
- single occurrence edit/delete；
- Today acknowledgement + recurring occurrence；
- Current Vector overlap negative case；
- timezone / date-only boundary。

## 5.5 一旦成立必须重排路线的发现

- 候选 host 无法稳定实现 tray / local persistence / packaging；
- recurrence exception 模型需要远高于当前估计的复杂度；
- Today acknowledgement 无法在不形成第二 truth 的情况下稳定实现；
- backup / migration 必须依赖更重的架构前置；
- Track / Plan / Today 真实数据消费者证明当前 ownership 不成立；
- first usable 一次集中实现的风险经证据证明过高；
- Owner 参考产品中真正高频使用的能力当前被错误 Deferred；
- 月 / 周 Calendar 本身造成过度开发而不服务核心价值。

## 5.6 最容易过早平台化的区域

- “所有 Plan 对象统一成万能 Item”；
- 通用 recurrence engine 超出 V0；
- Sources / Update Mode → 同步平台；
- AI-assisted Track Update → Agent platform；
- Custom Functions → Page Builder / Plugin SDK；
- Milestones → 完整项目管理；
- Today completion → Habit / analytics；
- backup → cloud sync；
- desktop shell → cross-platform framework-first architecture。

## 5.7 UI Reference 误导风险

参考图只能借鉴：

- 信息层级；
- 密度；
- 导航；
- 卡片与状态表达；
- desktop feel。

不得因为参考图存在以下模块就自动进入 Scope：

- Habit / streak；
- Dashboard analytics；
- Projects / Milestones；
- Knowledge；
- Finance / Health；
- AI chat；
- Plugin / widgets marketplace。
