## 1. Product Direction

Personal Workbench 当前正式方向是：

> **长期驻留在电脑上的个人信息与行动桌面（Personal State / Information & Action Desktop）。**

它不是一个替 Owner 自动管理人生的监督系统，也不是把 Calendar、Todo、Knowledge、Habit、Finance、Health 和 AI 一次性重新做一遍的超级 App。

它首先解决一个现实问题：

> Owner 已经拥有大量长期规划、个人资料、未来安排和日常事项，但这些信息分散在 ChatGPT、GitHub、脑中和其它工具里，缺少一个长期驻留、能持续看清并直接维护“长期状态 → 未来计划 → 今日信息”的个人工作台。

---

## 2. Target User

当前唯一核心用户：**Owner 本人**。

V0 优先适配 Owner 的真实桌面使用方式，不为假想团队、多租户、企业权限或公共 SaaS 场景增加复杂度。

---

## 3. Primary Purpose

> **把散落在长期规划、个人知识、未来安排和日常事项中的重要信息组织成一个长期驻留、可直接查看和编辑的个人工作台，使 Owner 能够从长期状态、未来计划和今日信息三个时间尺度持续看清自己的当前生活局面，并在使用电脑时快速明确当前值得关注和处理什么。**

Workbench 的价值不是替 Owner 做所有工作，而是：

```text
让我知道
→ 让我看清
→ 让我方便修改
→ 然后进入真正完成工作的工具
```

---

## 4. Job To Be Done

> 当我的长期规划、当前进度、未来安排和今天需要关注的信息散落在不同地方时，我希望打开一个长期驻留的个人工作台，就能快速知道我长期在推进什么、未来怎么安排、今天具体有什么，并能直接修改这些信息，而不需要反复回忆、翻查多个工具或重新规划。

---

## 5. Core Value

> **把“长期状态 → 未来计划 → 今日信息”组织成一套连续、清晰、低维护、可直接编辑的个人视图。**

三个 CORE 时间尺度：

```text
Tracks
= 我长期在推进什么？现在到哪里？

Plan
= 我未来准备怎么安排？有什么需要记住？

Today
= 今天我需要知道什么？
```

Today / Plan / Tracks 是同一套 Personal State 的三个视角，不应长期维护彼此冲突的第二份事实。

---

## 6. Product Structure

当前批准的稳定产品结构：

```text
PERSONAL WORKBENCH

CORE
├─ Today
├─ Plan
└─ Tracks

CUSTOM
└─ Future / 只有真实专业需求出现后再逐步增加
```

### CORE

CORE 是所有生活领域共享的基础能力。

### CUSTOM

Custom Functions 未来可以针对 CPA、求职或其它领域增加专用页面；可独立存在，也可关联一个或多个 Track。

V0 **不**建设 Plugin Marketplace、SDK、Low-code Page Builder 或通用扩展平台。

---

## 7. V0 Strategy

当前批准的 V0 厚度：

> **Thin Tracks + Usable Plan + Derived Today**

选择理由：

- 只做 Plan + Today 太薄，容易退化为漂亮 Calendar / Todo 首页；
- 一次性建设完整 Personal OS 太厚，会造成 Scope Explosion；
- Thin Tracks + Usable Plan + Derived Today 是第一次能真正把长期状态、未来安排和今天信息连起来、并可通过日常使用验证的最小有意义纵向。

---

# 8. Today｜V0 Required

## 8.1 Role

Today 是默认首页和最高频输出界面。

目标：Owner 打开 Workbench 后，应能很快回答：

> **“我现在处于什么阶段？今天具体有什么值得我关注？”**

Today 尽量不拥有第二份业务数据，而主要从 Plan / Tracks 派生当前日期相关内容。

## 8.2 Current Vector

- Current Vector 由 `Plan` 拥有；
- 是有开始 / 结束日期的特殊时间区间；
- 同一天最多一个生效 Vector；
- 用于表达当前阶段主要注意力方向；
- 没有 Vector 时显示中性空状态；
- 不使用 Completed 语义。

## 8.3 Today's Schedule

Today 展示 Plan 中当天发生的：

- 单次事项；
- 循环事项的当日 occurrence。

支持轻量 `Completed` 反馈，只用于让当天界面保持清晰，不建立连续打卡、完成率或自律评分系统。

循环事项完成只影响当天 occurrence，不终止整个循环定义。

## 8.4 Reminder / Memo

Today 只展示：

- 日期 / deadline 为今天的 Reminder；
- 展示日期为今天的 Memo。

Today 默认不展示：

- 未来 Reminder / Memo；
- Unscheduled；
- 全部 Tracks；
- 未来多日预告；
- 完成率、Habit streak、自律评分。

---

# 9. Plan｜V0 Required

## 9.1 Role

Plan 是 Workbench 自己拥有的未来安排与注意力配置中心。

V0 不依赖 Google Calendar 才能成立。

## 9.2 Calendar

V0 至少提供：

- Workbench 自有 Calendar 数据；
- 默认月视图；
- 月 / 周切换；
- 当前不要求 Day View。

## 9.3 Scheduled Item

至少支持：

### 单次事项

- Title；
- Date；
- Start / End Time；
- 可选 Track Link。

### 循环事项

至少支持常见重复模式：

- 每天；
- 每周指定星期；
- 开始日期；
- 可选结束日期；
- 时间段；
- 可选 Track Link。

循环事项不是 Habit Tracker，不要求连续天数和完成率。

## 9.4 Unscheduled

语义：

> **Owner 已决定近期要做，但尚未决定具体时间。**

边界：

- 不自动进入 Today；
- V0 不发展为完整 Todoist；
- 不要求子任务、看板或复杂 Priority 系统。

## 9.5 Reminder

表达某日期 / 时间需要 Owner 注意的信息；当天由 Today 读取。

## 9.6 Memo

表达某个未来日期希望再次看到的一段信息，不一定是任务；当天由 Today 读取。

## 9.7 Track Link

Plan Item 可选关联一个 Track，但不强制。

例如：

```text
CPA 会计学习 → Track: CPA
理发 → No Track
```

不得依赖标题关键字猜测 Track 关系。

---

# 10. Tracks｜V0 Required

## 10.1 Role

Tracks 回答：

> **我人生中有哪些正在长期推进的重要事情，它们当前分别处于什么真实状态？**

Tracks 不是 Todo List、打卡器或复杂项目管理系统。

## 10.2 Thin Track Model

V0 至少包含：

```text
Name
Long-term Goal
Current Phase
Current Real State
Near-term Direction
Sources（可选）
Update Mode（可选 / 为未来模型预留）
Last Updated
Status
```

“进度”以真实状态描述为主，不要求每日打卡，也不默认用百分比推算。

## 10.3 Lifecycle

```text
Active
Completed
Archived
```

Tracks 首页默认只显示 Active，并提供 Completed / Archived 的独立入口。

## 10.4 Milestones

状态：**OPEN / NOT REQUIRED FOR V0**。

Milestones 可能对长周期 Track 有价值，但目前没有足够真实使用证据，不因为参考产品存在该功能就加入 V0 Required。

---

## 11. Core Relationship / Ownership Intent

产品层关系：

```text
Tracks
长期事项与当前真实状态
        ↓ 可选关联
Plan
未来安排 / Calendar / Reminder / Memo / Vector / Unscheduled
        ↓ 按今天过滤
Today
当前日期的信息切片 / 默认首页
```

明确不是：

```text
Tracks
→ 自动生成 Plan
→ 自动监督执行
→ 自动评价
→ 自动重排人生
```

后续 Architecture 必须把 authoritative state 与 derived view 分清，避免 Today / Plan / Tracks 形成多份互相冲突的 live truth。

---

## 12. Product Experience Requirements

### PE-01｜Desktop / Persistent Feel

Workbench 应具有**适合长期挂起、频繁唤起的桌面工作台体验**。

这是一项产品体验要求，不等于现在冻结 Electron / Tauri / Native / Web 等实现技术。

### PE-02｜Today as Default Entry

正常打开 / 唤起 Workbench 时，Today 是默认主入口。

### PE-03｜Low Maintenance

Workbench 的维护成本必须明显低于它节省的回忆、查找和重新规划成本。

### PE-04｜Owner Control

系统帮助 Owner 看清和维护状态，不以监督、评分、强制执行或自动替 Owner 决策为核心。

---

## 13. AI Position

AI **不是 V0 成立的前提**。

长期结构：

```text
Workbench
= Core Personal State owner

AI / GitHub / Codex / external sources
= 可选的信息来源、辅助分析与更新能力
```

未来 AI 可以：

- 从 GitHub 等来源提出 Track 更新建议；
- 帮助整理复杂规划；
- 根据 Owner 明确要求修改状态；
- 支持后续 Custom Functions。

但 V0 即使没有 AI 自动写入，也必须作为独立产品成立。

### AI-assisted Track Update

产品模型可预留：

```text
Manual
Confirm before update
Auto update
```

但 **GitHub Source / AI Suggested Update 不属于当前 V0 Required**。默认原则仍是 `Source Change != Track Change`，未来如实现更新建议，默认优先 `Confirm before update`。

## 15. Non-scope for V0

V0 不负责：

- 自动管理或监督 Owner 的人生；
- 自律评分 / 连续打卡 / Habit streak；
- 完整 GTD / Todoist clone；
- 完整项目管理系统；
- 完整个人知识库；
- 替代所有实际工作工具；
- 同时实现 Calendar / Knowledge / Habit / Finance / Health / AI 全套系统；
- 面向团队 / 企业的组织权限；
- 预建大型通用插件或自动化平台。

## 16. Product Success Criteria

### 16.1 Daily Utility

Owner 在真实使用电脑时，会自然让 Workbench 长期挂起或频繁唤起，并愿意先看 Today。

### 16.2 Today Clarity

Owner 打开 Today 后，可以很快回答：

- 当前阶段主要方向是什么；
- 今天有什么安排；
- 今天有什么 Reminder / Memo。

### 16.3 Planning Utility

Owner 在查看或修改未来安排时，会自然使用 Plan，而不是主要依赖脑内记忆或临时清单。

### 16.4 Long-term State Utility

Owner 能在 Tracks 中快速看到 CPA、求职、项目等长期事项的当前真实状态。

### 16.5 Low Maintenance

维护 Workbench 所花的时间明显低于它节省的回忆、查找和重新规划成本。

### 16.6 Real Replacement Signal

经过真实使用后，自然形成：

```text
今天看什么 → Today
未来怎么排 → Plan
长期到哪里 → Tracks
```

而不是 Workbench 只成为漂亮但很少打开的 Dashboard。

---

## 17. Product Failure Conditions

出现以下情况之一时，应重新评估产品或 V0：

1. 大量信息需要重复手工录入，维护成本过高；
2. 界面漂亮，但不能更快明确当前局面；
3. 产品退化成大量 checkbox / Priority / Subtask 的 Todo App；
4. 完成率、连续打卡、自动评价变成核心；
5. Scope 扩张为 Calendar / Knowledge / Habit / Finance / AI / Health 全家桶；
6. GitHub、Tracks、Plan、Custom Page 等出现多份互相冲突的事实；
7. Today 重新塞入未来事项、全部 Tracks、Unscheduled 等大量信息；
8. Owner 花在管理 Workbench 上的时间超过现实行动；
9. 某个外部平台重新成为产品能否成立的核心单点依赖；
10. 真实使用习惯不成立，Owner 仍极少打开 Workbench。

---

## 18. Hard Product Constraints

当前产品层必须保持：

- **Core Personal State 由 Workbench 自己拥有**，不能把某个外部 SaaS UI 变成产品成立的前提；
- **Owner-controlled**：关键状态修改和方向判断不能默认被自动监督系统替代；
- **Low maintenance**：不能通过大量录入换取“看起来完整”；
- **Derived Today**：Today 默认是当前日期投影，不成为第二 live truth；
- **Scope discipline**：V0 只证明 Today / Plan / Tracks 的真实日常价值；
- **桌面高频体验**：应适合长期驻留 / 高频唤起，但具体技术承载待 Architecture / Reference Audit 决定。
