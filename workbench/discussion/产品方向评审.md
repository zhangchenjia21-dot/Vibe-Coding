## 1. Review Context

### 1.1 原 AI Collaboration 路线

原 Personal Workbench V0 的核心闭环为：

```text
ChatGPT
→ Selected Text
→ Send to Codex
→ Codex 执行
→ GitHub
→ 当前 ChatGPT Conversation 一键 Review
→ Fix / Accept
```

原 Primary Purpose：

> 减少 Owner 在 ChatGPT → Coding Agent → GitHub → ChatGPT Review 之间的复制、切换、状态观察和人工提醒等机械协调劳动。

### 1.2 当前核心 Blocker

经过技术分析，原路线的核心体验高度依赖于对现有 ChatGPT Web 的可靠嵌入 / 接管，包括：

- 保留 Owner 当前登录 / Session；
- Projects；
- conversation continuity；
- 文件上传；
- 在 GPT 回复中可靠获取任意 Selected Text；
- 向当前 ChatGPT conversation 进行可靠的一键 Review Handoff。

这些能力当前存在较高技术与维护风险，且依赖外部平台行为。

### 1.3 当前讨论中的处理倾向

原 AI Collaboration 不再作为当前产品方向继续设计。

Owner 已在本轮讨论中明确表达：

> 当前暂时放弃 AI Collaboration；未来如果重新产生真实需要，可以再添加，但当前不考虑。

因此本 Review 建议将其视为：

**DEFERRED / FUTURE**

而不是把整个 Personal Workbench 继续建立在该路线之上。

是否正式 Promotion 为 current direction，仍待 Owner 对本文件整体方向做最终批准。

## 2. Product Discovery｜Current Reality

Owner 当前已经拥有大量规划、信息和工具，但缺乏整体的当前视图：

- 通过 ChatGPT 讨论和制定长期 / 阶段规划；
- 通过 GitHub 建立个人知识库、保存长期信息、正式规划与历史资料；
- 日程 / Todo 使用过 Google Calendar，但目前使用较少，现有数据价值不高；
- 很多长期事项的“当前真实状态”仍主要依靠 Owner 自己记忆；
- 不同领域的信息存在，但散落在 GPT、GitHub、日历、脑中和各类工具中。

### Real Pain

当前最明确的问题不是“缺少规划工具”，而是：

> **Owner 已经有很多规划和信息，但缺少一个能够长期驻留、集中呈现和直接维护当前生活状态的个人工作台。**

以 CPA 为例：

```text
GPT 制定长期 CPA 规划
→ 规划存在于聊天 / 资料中
→ 实际学习进度长期主要靠脑子记
→ 未来学习安排缺少一个自己的整体日历
→ 每天也缺少一个清晰的“今天学什么 / 今天要注意什么”界面
```

Owner 不希望系统变成监督 / 打卡 / 自律评分系统。

目标是：

> **让我知道、让我看清、让我方便修改。**

## 3. Personal Workbench｜Primary Purpose Candidate

### 3.1 Product Positioning Candidate

Personal Workbench 更接近一个：

> **长期驻留在电脑上的 Personal Desktop / Personal Workbench。**

它不是一个需要专门“打开来管理人生”的后台，也不是把所有软件重新做一遍。

理想使用方式：

```text
打开 / 使用电脑
→ Personal Workbench 经常默认挂起
→ 快速看清当前主方向、今天事项、提醒 / 备忘
→ 明确现在应该关注什么
→ 再进入真正完成工作的工具
```

例如：

- CPA → 教材 / 浏览器 / 学习资料；
- 求职 → ChatGPT / 招聘网站 / 邮箱；
- Coding → ChatGPT / Codex / GitHub；
- 其它事项 → 对应真实工具。

Workbench 当前不需要完成所有工作；它首先负责成为 Owner 的**当前信息与行动桌面**。

### 3.2 Primary Purpose Candidate

> **Personal Workbench 将散落在长期规划、个人知识、未来安排和日常事项中的重要信息组织成一个长期驻留、可直接查看和编辑的个人工作台，使 Owner 能够从长期状态、未来计划和今日信息三个时间尺度持续看清自己的当前生活局面，并在使用电脑时快速明确当前值得关注和处理什么。**

### 3.3 JTBD Candidate

> 当我的长期规划、当前进度、未来安排和今天需要关注的信息散落在不同地方时，我希望打开一个长期驻留的个人工作台，就能快速知道我长期在推进什么、未来怎么安排、今天具体有什么，并能直接修改这些信息，而不需要反复回忆、翻查多个工具或重新规划。

### 3.4 Core Value Candidate

> **不是替 Owner 自动管理人生，而是把“长期状态 → 未来计划 → 今日信息”组织成一套连续、清晰、可维护的个人视图。**

核心原则：

```text
Tracks
= 我长期在推进什么？现在到哪里？

Plan
= 我未来准备怎么安排？有什么需要记住？

Today
= 今天我需要知道什么？
```

# 7. Today｜Candidate V0

## 7.1 角色

Today 是 Workbench 的默认首页和主要输出界面。

> **只呈现今天真正需要占用注意力的信息。**

它尽量不重复拥有数据，而主要从 Plan / Tracks 中派生今天相关内容。

## 7.2 Current Vector

Current Vector 由 `Plan` 拥有，是一种有明确开始 / 结束日期的特殊时间区间对象。

例如：

```text
2026-09-01 → 2026-09-20
Current Vector：四大秋招优先
说明：重点准备面试，CPA 保持稳定学习
```

Today 根据当天日期自动读取当前生效 Vector。

确认原则：

- 同一天最多只有一个 Current Vector；
- Vector 描述中可以表达主次；
- 若当前日期没有 Vector，Today 显示类似“当前暂无重点方向 / 近期无特别重要目标”的中性信息；
- Current Vector 不具备 Completed 状态。

## 7.3 Today's Schedule

Today 展示 Plan 中当天发生的：

- 单次任务；
- 循环任务的当日 occurrence。

今日事项卡片支持轻量 Completed 状态：

```text
普通状态
→ Owner 点击
→ 显示已完成（如划线 / Check / 降低视觉权重）
```

目的：

> 让当天界面保持清晰，而不是建立监督 / 统计体系。

循环任务点击完成时，只完成当天这一期，不终止整个循环。

## 7.4 Reminder / Memo Filter

Today 只展示：

- 日期 / deadline 恰好为今天的 Reminder；
- 展示日期恰好为今天的 Memo。

明确不展示：

- 明天 / 未来 Reminder；
- 未来 Memo；
- 全部 Tracks；
- Unscheduled；
- 未来几天预告；
- 完成率、打卡统计、习惯评分。

## 7.5 Today Success Feeling

Owner 打开 Today 后，应能在很短时间内回答：

> **“我现在处于什么阶段？今天具体有什么值得我关注？”**

# 8. Plan｜Candidate V0

## 8.1 角色

Plan 是 Workbench 自己拥有的未来安排与注意力配置中心。

当前不依赖 Google Calendar。

## 8.2 Calendar

V0 Candidate：

- Workbench 自己拥有 Calendar 数据；
- 默认 **月视图**；
- 提供 **月 / 周切换按钮**；
- 月视图用于整体、粗粒度观察；
- 周视图用于更具体的时间安排；
- 当前不要求 Day View。

## 8.3 Calendar Item

至少支持：

### 单次任务

```text
标题
日期
开始 / 结束时间
可选 Track 关联
```

### 循环任务

至少支持常见重复模式，例如：

- 每天；
- 每周指定星期；
- 开始日期；
- 可选结束日期；
- 时间段；
- 可选 Track 关联。

循环任务不是 Habit Tracker，不要求连续天数 / 完成率。

## 8.4 Unscheduled

Plan 保留独立 `Unscheduled / 待安排` 区域。

语义：

> **Owner 已决定近期要做，但尚未决定具体时间。**

边界：

- 不自动进入 Today；
- 不要求发展成完整 Todoist；
- 第一版不需要子任务 / 看板 / 复杂 Priority 系统。

## 8.5 Reminder

Reminder 表达：

> 某个日期 / 时间需要提醒 Owner 注意的信息。

当天由 Today 读取。

## 8.6 Memo

Memo 表达：

> 某个未来日期希望重新看到的一段信息，不一定是需要完成的任务。

当天由 Today 读取。

## 8.7 Current Vector

Plan 中可创建跨日期 Current Vector；Today 只读取当前生效的唯一 Vector。

## 8.8 Track Link

Plan 中的任务 / 日程可以**可选关联**一个 Track，但不强制。

例如：

```text
CPA 会计学习
→ Track：CPA

理发
→ 无 Track
```

意义：

- Track Detail 可以看到自己的近期 Plan；
- Today 可以在必要时提供 Track Context；
- Custom Page 以后可以读取相关 Plan；
- 不需要通过标题关键字猜测关联关系。

# 9. Tracks｜Candidate V0

## 9.1 角色

Tracks 回答：

> **我人生中有哪些正在长期推进的重要事情，它们当前分别处于什么真实状态？**

Tracks 不是打卡器、Todo 列表或复杂项目管理系统。

## 9.2 Track Basic Model

当前推荐的薄模型：

```text
Name
Long-term Goal
Current Phase
Current Real State
Near-term Direction
Sources
Update Mode
Last Updated
Status
```

以 CPA 为例：

```text
名称：CPA
长期目标：完成 CPA 专业阶段六科
当前阶段：会计第一轮学习
当前真实状态：目前学到第 8 章
近期方向：继续推进会计第一轮
```

“进度”由 Owner 按现实需要主动记录 / 更新，不要求每日打卡，也不自动根据完成率推算。

## 9.3 Track Lifecycle

确认：

```text
Active
Completed
Archived
```

默认 Tracks 首页只显示 `Active`。

同时保留：

- Completed 入口；
- Archived 入口。

语义：

- Active = 当前仍在现实中推进 / 关注；
- Completed = 已自然完成、值得保留；
- Archived = 不再需要出现在正常视野，但历史不删除。

## 9.4 Source-backed Track

Track 可以绑定外部信息来源，当前最明确的是 GitHub 个人知识库。

候选关系：

```text
GitHub
= 长期资料、完整规划、历史记录

Track
= 从这些资料中提炼出的当前状态
```

Workbench 不需要复制 GitHub 全文，而是把长期资料压缩成：

- 长期目标；
- 当前阶段；
- 当前真实状态；
- 近期方向。

## 9.5 AI-assisted Update

候选维护模式：

```text
Manual
Confirm before update
Auto update
```

讨论确认：

- 三种模式未来都可支持；
- 默认推荐 `Confirm before update`；
- `Source Change != Track Change`；
- GitHub Source 更新后，AI 可以生成 Track 更新建议；
- Owner 可选择：应用 / 编辑后应用 / 忽略；
- Auto update 只在 Owner 明确授权某 Track 后使用。

V0 是否直接实现 AI-assisted Update 仍需在架构 / 实现量评估后决定；其产品模型应预留，但不应成为 V0 成立的必要前提，除非后续 Owner 再次提升其优先级。

## 9.6 Milestones

状态：**OPEN**

Milestones 对 CPA 等跨度很长的 Track 可能有价值，但 Owner 当前没有实际使用经验。

建议：

- 不因为参考图有 Milestones 就自动加入 V0；
- 先使用 Track 薄模型；
- 如产品评审认为长期阶段结构不可缺，再提升为 V0 Requirement。

## 11. Candidate V0 Thickness Comparison

### 11.1 最薄版本｜Too Thin Candidate

```text
Plan 基础日历
+ Today 今日视图
```

优点：开发最快。

问题：长期方向仍然缺失，很容易退化为漂亮 Calendar / Todo 首页，不能充分解决“整体感”问题。

### 11.2 中等版本｜Recommended Candidate

```text
Thin Tracks
+ Usable Plan
+ Derived Today
```

Plan 包含：

- 月 / 周日历；
- 单次 / 循环任务；
- Unscheduled；
- Reminder；
- Memo；
- Current Vector；
- Track optional link。

Tracks 使用薄状态模型。

Today 作为严格过滤的默认首页。

优点：

- 首次真正把长期状态、未来计划和今天信息连起来；
- 仍然没有进入复杂 Personal OS；
- 第一版即可进行真实日常使用测试。

当前本轮讨论明显倾向该版本。

### 11.3 过度版本｜Reject for V0

包括但不限于：

- 完整 Todo / GTD 系统；
- Habit Tracker；
- 自动监督 / 自动重排；
- Google Calendar 双向同步；
- 完整知识库；
- Finance / Health；
- Weekly Review Automation；
- CPA 专用页；
- 求职专用页；
- Plugin Marketplace；
- Low-code Page Builder；
- 通用 Agent / AI Orchestration；
- 大规模 AI 自动维护系统。

这些均不应成为 Candidate V0 的前置条件。

更健康的长期结构：

```text

= 拥有自己的 Core Personal State

= 可以成为信息来源、辅助分析与更新能力
```

未来 AI 可以：

- 从 GitHub 资料提炼 Track 更新建议；
- 根据 Owner 明确要求更新 Workbench；
- 帮助整理复杂规划；
- 后续按真实需求协助 Custom Functions。

但 V0 即使没有 AI 自动写入，也应能作为独立产品成立。

## 15. Product Success Criteria Candidate

新方向不能以“Today / Plan / Tracks 页面已经做出来”作为成功标准。

### 15.1 Daily Utility

Owner 在真实使用电脑时，会自然把 Workbench 长期挂起或频繁唤起，并愿意先看 Today。

### 15.2 Today Clarity

Owner 打开 Today 后，可以很快回答：

- 当前阶段的主要方向是什么？
- 今天具体有什么安排？
- 今天有什么 Reminder / Memo？

而不是重新翻计划或回忆。

### 15.3 Planning Utility

Owner 在想看 / 修改未来安排时，会自然进入 Plan，而不是必须依靠脑子或另建临时清单。

### 15.4 Long-term State Utility

Owner 能在 Tracks 中快速看到 CPA、求职、项目等长期事项的当前真实状态，而不是主要靠脑子记。

### 15.5 Low Maintenance

维护 Workbench 所花的时间明显低于它节省的回忆、查找和重新规划成本。

### 15.6 Real Replacement Signal

经过一段真实使用后，Owner 会自然形成：

```text
今天看什么 → Today
未来怎么排 → Plan
长期到哪里 → Tracks
```

而不是 Workbench 只成为一个漂亮但很少打开的 Dashboard。

## 16. Failure Conditions

如出现以下情况，应重新评估产品方向：

1. **维护成本过高**：大量信息需要重复手工录入；
2. **Dashboard-only**：界面漂亮，但不能帮助 Owner更快明确当前局面；
3. **Todo App 化**：大量 checkbox、优先级、子任务淹没长期信息；
4. **监督系统化**：完成率、连续打卡、自动评价成为核心；
5. **Scope Explosion**：Calendar / Knowledge / Habit / Finance / AI / Health 一次性全部进入；
6. **重复事实源**：GitHub、Tracks、Custom Page 各存一份互相不一致的信息；
7. **Today 信息过载**：Unscheduled、未来事项、全部 Tracks 等重新塞回默认首页；
8. **计划管理超过现实行动**：Owner 花太多时间维护 Workbench；
9. **外部平台依赖重新成为核心瓶颈**；
10. **真实使用习惯不成立**：Owner 仍很少打开 Workbench，继续完全依靠脑子 / 零散工具。
