## A. Calendar / Recurrence / Date Semantics

### Google Calendar API｜Recurring Events

https://developers.google.com/workspace/calendar/api/guides/recurringevents

用于支持：

- recurring parent / instance 区分；
- instance 的 `recurringEventId`；
- `originalStartTime` 作为 occurrence 原始身份锚点；
- single-instance modification 形成 exception；
- “this and following” 通常通过截断旧 series + 新建 series 处理。

### Microsoft Graph｜Event Resource

https://learn.microsoft.com/en-us/graph/api/resources/event?view=graph-rest-1.0

用于支持：

- `seriesMaster` / `occurrence` / `exception` / `singleInstance`；
- `seriesMasterId`；
- `originalStart`。

### Outlook Support｜Recurring Meeting Edit Scope

https://support.microsoft.com/en-us/outlook/create-modify-or-delete-a-meeting-request-or-appointment-in-outlook-com

用于确认成熟 Calendar 产品确实向用户暴露单次 / series / following 等不同修改 scope，但并不意味着 Workbench V0 必须承载全部复杂度。

### Apple EventKit｜EKEvent

https://developer.apple.com/documentation/eventkit/ekevent

重点相关概念：

- detached recurring event instance；
- occurrence date / recurrence relationship。

### RFC 5545｜Internet Calendaring and Scheduling Core Object Specification

https://www.rfc-editor.org/rfc/rfc5545.html

用于支持：

- UID + RECURRENCE-ID；
- recurrence instance identity；
- DATE 与 DATE-TIME 的语义区分；
- local time / UTC / TZID；
- range / THISANDFUTURE 的复杂性。

## B. Today / Planner / Personal Dashboard

### Things｜Today

https://culturedcode.com/things/support/articles/4001304/

用于支持：

- Today 更接近 current-time filter / projection，而不是第二份独立 task truth；
- Today / Upcoming / Anytime / Someday 的职责分离；
- 不需要把 backlog / future / all state 堆到 Today。

### Akiflow｜Today Page

https://product.akiflow.com/articles/0741055-today-page

用于支持：

- Today 聚焦已经 plan 到当天的内容；
- Today 作为当前执行视图，而不是复制独立业务数据。

### Sunsama｜Getting Started / Daily Planning

https://help.sunsama.com/docs/getting-started/setting-up-your-account/

用于支持：

- daily plan 与 backlog 分离；
- 今天视图应聚焦真正计划到当天的内容。

## H. SQLite / Persistence / Recovery

### SQLite｜Application File Format

https://www.sqlite.org/appfileformat.html

用于支持：

- SQLite 适合作为 application file format；
- 单文件、transaction、schema、query / relational structure 等能力；
- 相比 pile-of-files 可减少应用自行维护一致性基础设施。

### SQLite｜Atomic Commit

https://www.sqlite.org/atomiccommit.html

用于支持：

- crash / OS failure / power loss 下 transactional durability 的设计基础。

### SQLite｜Database File Format

https://www.sqlite.org/fileformat.html

用于支持：

- journal / WAL / header / user_version 等底层事实；
- live database state 不应被简单等同于只复制主 `.db` 文件。

### SQLite｜Online Backup API

https://www.sqlite.org/backup.html

用于支持：

- live database 的 consistent snapshot / manual backup 路径。

### SQLite｜VACUUM INTO

https://www.sqlite.org/lang_vacuum.html#vacuuminto

作为另一种生成 standalone database backup 的候选方式。

### SQLite｜PRAGMA integrity_check

https://www.sqlite.org/pragma.html#pragma_integrity_check

用于支持：

- backup / restore 前后的数据库完整性验证。

### SQLite｜ALTER TABLE / Migration Guidance

https://www.sqlite.org/lang_altertable.html

用于支持：

- schema evolution 需要明确 transactional migration；
- 对复杂 schema change 不应依赖“删库重建”。
