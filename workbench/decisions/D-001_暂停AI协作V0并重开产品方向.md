# D-001｜暂停 AI Collaboration V0 并重新打开产品方向

Status：**DECIDED**  
Date：2026-09-06  
Owner：用户（最终 Product Owner）

## Decision

1. 原 **AI Collaboration V0** 不再作为 Personal Workbench 的 current Product / Roadmap / Architecture 基线。
2. 将该路线及其核心文件、未审核路线 / 架构草案与依赖旧 V0 的设定整体移入 `99_归档/workbench/AI协作路线_V0/`。
3. AI Collaboration V0 状态为 **HOLD / HISTORICAL**，不是永久 REJECTED。
4. Personal Workbench 回到 **Stage 0｜Product Direction Re-evaluation / Pivot Discovery**。
5. `Personal OS / Life Operating System` 是当前重点探索的候选方向，但**本决定不批准它成为新的 current Product Definition**。
6. 新方向必须重新经过 Owner Discussion、Product Definition、G0.1 / G0.2 与后续 Route Freeze，不继承旧路线的 Gate PASS。

## Context

旧 V0 的核心体验要求 Workbench 能继续使用 Owner 真实的 ChatGPT Web 工作流，并实现：

- 已有登录 / Session 与核心体验延续；
- GPT 回复 Selected Text → Agent；
- Agent / GitHub 完成后的 current ChatGPT conversation Review Handoff。

经过 02 / 03 与 Owner 的讨论，关键 ChatGPT Web 集成路径被判断存在高可行性与维护风险。由于该 seam 直接支撑旧 V0 的 Core Value，继续沿旧路线投入会产生显著沉没成本。

## Why

- 避免为了保住旧产品定义而围绕脆弱技术 seam 继续堆工程复杂度；
- 避免旧 `产品定义 / Scope / Task Axis / Architecture Questions` 在 active tree 中误导下一轮 Product Discovery；
- 保留历史证据与 future revisit 可能性，同时恢复产品层面的选择自由；
- 让下一轮围绕 Owner 的真实生活 / 工作痛点重新决定第一版最值得解决的问题。

## Alternatives considered

### A. 保持 AI Collaboration V0 为 current，继续寻找 workaround

未采用。当前关键 blocker 直接击中 Non-negotiable Core，继续推进容易形成 architecture anchoring 与沉没成本。

### B. 立即把 Personal OS 宣布为新 current Product

未采用。当前只有参考图、初步兴趣与候选产品模型，尚未完成 Owner Product Discovery。

### C. 归档旧路线，重新打开 Product Direction

**采用。** 保留历史，但不让历史继续拥有 current authority。

## Consequences

- `current/产品定义.md` 被撤出 active current 并归档；
- 旧 G0.1 / G0.2 PASS 变为路线历史，不适用于新方向；
- 03 旧 Draft Task Axis / Architecture Questions 不再参与下游；
- `current/` 只保留中性的项目总纲与项目状态；
- 当前下一主线回到 `01｜产品定义` 做 Product Pivot Discovery；
- 02 / 03 / 04 / 05 不得依据旧路线自动继续；
- implementation 继续未授权。
