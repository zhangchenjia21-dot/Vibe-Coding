# 18｜酒馆游戏：资料库资源层与世界创作集成裁定 v1.1

> [!abstract] 核心裁定
> 酒馆游戏继续保留 **世界包 / 角色卡 / 拓展包** 三类主资产架构；“资料库”定义为一层可独立复用、可被主资产绑定和按需检索的 **资料资源层**，不是第四类并列主资产。
>
> v1.1 新增最重要的时序裁定：**资料库属于后置增量功能。当前只冻结长期产品与架构方向，不进入三类主资产主链的首轮协议、适配器、Creator 和游戏创建闭环。只有“三类主资产纵向闭环门槛”全部 PASS 后，资料库才允许进入正式开发。**
>
> 正式冻结：**资料库不是局内正式状态，也不是整库上下文。**

---

## 0. 为什么需要资料库，但不改成四类主资产

当前三类主资产继续承担稳定分权：

```text
世界包
= 世界身份 / 世界规则 / 地理社会框架 / T0 开局事实 / 默认组合

角色卡
= 重要人物定义 / 人格 / 决策逻辑 / 初始人物证据

拓展包
= 可复用或世界专属的机制 / 领域语义 / 玩法能力
```

大型时代资料、历史资料、制度资料、研究资料若全部塞进世界包，会造成：

- 世界包正文无限膨胀；
- 多世界重复维护同一时代资料；
- 普通回合上下文被误认为需要整包常驻；
- Creator 无法区分“世界根定义”和“大量可检索参考资料”；
- 原历史参照、史料来源、争议记载等内容被误当成当前世界状态。

因此长期架构新增资料资源层，但三类主资产产品定位不变：

```text
三类主资产
├─ 世界包
├─ 角色卡
└─ 拓展包

资料资源层
└─ 资料库
```

---

## 1. 资料库的唯一定位

资料库回答：

> **“有哪些长期可复用、可检索、可引用，但不应直接成为当前局内正式状态的大量资料？”**

典型内容包括：

- 历史与时代背景；
- 政治制度、官制、军制、经济制度、社会文化资料；
- 地理、地名、区域背景；
- 技术、宗教、学术、行业知识；
- 原历史事件与人物轨迹；
- 史料来源、争议、不同版本；
- 世界创作中的术语、设定解释和大型参考条目；
- 可供世界包 / 角色卡 / 拓展包引用的定义来源与研究证据。

资料库不拥有当前人物、组织、政治、经济、战争、任务、关系、玩家知识或正式结果状态。

---

## 2. 世界包与资料库不是同一种上下文来源

正式区分：

```text
世界包
= 世界根来源
= 世界身份与基础语义锚点

资料库
= 参考资料来源
= 大量按需检索的参考内容
```

世界包可以向运行时提供少量高价值根语义，例如当前世界、时代、基调、核心规则、开局锚点和正式资产组合。

资料库默认采用：

```text
已绑定资料库
!= 当前运行相关
!= 当前模型可见
```

整库内容不得因为“本局绑定了该资料库”就进入模型上下文。

---

## 3. 资料库未来在游戏中的三类价值

### 3.1 世界定义 / 初始化参考来源

```text
资料库条目
↓ 创作 / 组合引用
正式领域定义
↓
当局游戏定义 / 状态
```

因此：

```text
资料库引用
!= 当局游戏正式定义
!= 局内正式状态
```

### 3.2 模型按需参考上下文

未来正确链：

```text
当前输入 / 当前职责
+
当前正式锚点
↓
确认需要某类资料
↓
从本局绑定资料库检索相关条目
↓
执行信息边界 / 玩家知识边界过滤
↓
生成最小充分资料切片
↓
与当前必要正式状态有界组合
↓
模型
```

禁止：

```text
整个资料库
→ 每回合上下文
```

### 3.3 Creator / AI 创作辅助来源

未来 Creator 可以用资料库检索世界背景、生成时代一致内容、检查设定冲突、整理大量笔记并提取为独立资料库。

这些能力在 v1.1 中只是长期产品语义，**当前不进入 Creator 主链实现范围**。

---

## 4. 资料库与玩家知识必须分离

正式冻结：

```text
资料库包含某事实
!= 玩家知道该事实
!= 当前模型应该看到该事实
```

资料库不能成为绕过隐藏信息规则的后台全知上下文。

---

## 5. 汉末三国历史参照与穿越玩法分权

长期目标保持：

```text
汉末三国历史与时代资料
→ 世界专属资料库

原历史参考 / 关键前提 / 史料 / 争议
→ 资料库中的历史参照部分

当前正式世界状态
→ 各正式事实拥有者 / Runtime

穿越与系统：历史辅助
→ 读取经过授权的历史参照资料
→ 不拥有原历史资料本身
```

穿越者可以利用原历史知识，但“有没有穿越者”不决定资料是否存在。

---

## 6. 世界专属政治 / 经济 / 战争资料的长期归宿

Shared Foundation 完成后，世界专属层不得为了旧资产结构继续维护第二套政治 / 经济 / 战争机制。

例如汉末三国长期目标：

```text
政治机制
→ 通用政治核心

经济机制
→ 通用经济核心

战争机制
→ 通用战争核心

汉末官制 / 政治文化 / 时代制度
汉末财赋 / 屯田 / 生产背景
汉末军制 / 兵种 / 战争环境
原历史人物与事件参照
→ 汉末三国历史与时代资料库
```

但本节描述的是**迁移终态**，不是当前资料库实现授权。

---

## 7. 资料库产品入口的长期方向

### 创建游戏

长期方向仍然是世界包优先：

```text
创建游戏
↓
选择世界包
↓
世界包详情 / 组合
└─ 世界资料
   ├─ 已绑定资料库
   ├─ 推荐资料库
   └─ 高级：添加 / 移除兼容资料库
```

普通玩家不增加强制“第四步：选择资料库”。

### Creator

长期方向仍然是：

```text
世界包
→ 资料与参考
→ 创建 / 导入 / AI 整理 / 引用 / 提取为独立资料库
```

产品上与世界包紧密结合，架构上允许独立复用。

**但这些界面和工作流全部属于后置增量功能，不纳入当前三类主资产 Creator 首轮闭环。**

---

## 8. 跨主资产引用的长期能力

长期允许：

```text
世界包 → 资料库
角色卡 → 资料库引用
拓展包 → 资料库引用
```

引用不等于复制，资料内容保持自己的来源与版本身份。

本能力同样等待资料库增量阶段再冻结机器表达。

---

## 9. 版本、绑定与现有游戏稳定性

长期产品语义保持：

```text
源资料库
→ 游戏绑定 / 选定修订
→ 按需参考投影
```

源资料库更新不得静默改写已有当局游戏定义、当前状态、已发生事件或玩家已知事实。

**具体版本、绑定、更新、迁移和导入导出协议不再属于当前 G9-03 / G9-04 首轮范围，等待资料库增量阶段冻结。**

---

## 10. 上下文规模原则

长期必须满足：

```text
资料库规模 ↑↑↑
普通无关回合上下文 ≈ 稳定
```

以及：

```text
绑定资料库数量 ↑↑↑
无关回合可见资料切片 ≈ 0
```

资料库检索必须有界、不饥饿、保留来源、遵守信息安全、不递归全文展开。

---

## 11. 当前 G9-02C 的传播

```text
G9-02C 核心设计
= 保持已冻结

G9-02C 当前实现
= 不新增资料库导入 / 索引 / 检索 / Creator 功能

资料库
= 不形成 02C blocker
```

02C 只需保持未来上下文来源可扩展，不要求实现真实资料库能力。

---

## 12. 三类主资产纵向闭环门槛｜资料库开发前置条件

资料库从“批准的架构储备”进入“正式开发任务”之前，以下条件必须**全部 PASS**。

### GATE-LIB-01｜三类主资产语义与协议完成

世界包、角色卡、拓展包必须已经完成当前主链所需的：

- `tavern-asset` 相关语义规范与治理规则；
- 最终首轮资产协议；
- 身份、版本、依赖、组合、运行绑定等机器表达；
- 对应审核和迁移闭环。

资料库不得为了赶进同一次协议冻结而扩大首轮协议范围。

### GATE-LIB-02｜三类主资产适配 / 导入 / 当局游戏绑定完成

必须能够把世界包、角色卡、拓展包从“我的资产库”真实带入新游戏，并形成稳定的当局游戏定义和运行状态。

### GATE-LIB-03｜Creator 三类主资产基础创作链完成

Creator 至少已经能够围绕世界包、角色卡、拓展包完成基本的：

- 创建；
- 编辑；
- AI 辅助；
- 校验；
- 保存；
- 导入 / 导出；
- 回到“我的资产库”继续使用。

不要求 Creator 所有高级功能全部完成，但三类主资产的核心创作链必须可实际使用。

### GATE-LIB-04｜“我的资产库 → 创建游戏”产品链完成

玩家必须已经能够：

```text
我的资产库
→ 查看 / 导入 / 管理三类主资产
→ 创建新游戏
→ 选择世界包
→ 选择 / 组合角色卡与拓展包
→ 完成组合校验
→ 正式创建游戏
```

这条主链没有资料库也必须完整成立。

### GATE-LIB-05｜三类主资产完整游玩纵向验证 PASS

必须至少存在真实资产组合证明：

```text
三类主资产创作 / 导入
→ 我的资产库
→ 创建新游戏
→ 初始化
→ 正常游玩
→ 领域机制与上下文工作
→ Save / Continue / Restore / Branch / Recovery
→ 可持续完整游玩
```

不能仅以“协议已写好”或“Creator 页面能打开”作为资料库开工条件。

### GATE-LIB-06｜主资产产品问题已先收口

若三类主资产仍存在阻塞性的协议、Creator、组合、导入、创建游戏或运行问题，优先修主链；资料库不得成为绕开主链问题的新工作流。

---

## 13. 资料库正式开发时机

正式时序：

```text
三类主资产 Shared Foundation / 语义收口
↓
三类主资产机器协议
↓
三类主资产适配 / 编译 / 当局游戏绑定
↓
“我的资产库”三类主资产管理与创建游戏组合
↓
Creator 三类主资产基础创作链
↓
真实资产组合端到端完整游玩 PASS
↓
【三类主资产纵向闭环门槛 PASS】
↓
资料库增量功能阶段
```

因此当前项目中：

- G9-02：不实现资料库；
- G9-03：首轮只冻结世界包 / 角色卡 / 拓展包机器协议；
- G9-04：首轮只实现三类主资产适配 / 编译 / 绑定；
- G9-05 Creator：首轮只要求三类主资产基础创作闭环；
- “我的资产库 → 创建游戏 → 完整游玩”仍属于资料库之前的必经产品门槛；
- 资料库的正式阶段编号**现在不预造**，等上述门槛真实 PASS 后再按当时路线插入 / 命名。

资料库可以在此之前继续记录架构原则、真实需求和迁移候选，但不得转化为实现任务、首轮协议 blocker 或 Creator 首轮 blocker。

---

## 14. 资料库增量阶段届时再冻结什么

只有 GATE-LIB-01..06 全部 PASS 后，资料库增量阶段才冻结 / 实现：

1. 资料库源身份、版本与完整性；
2. 世界包与 0..N 资料库绑定；
3. 默认 / 推荐 / 可选资料组合；
4. 独立 / 内嵌 / 引用的机器表达；
5. 游戏绑定、修订、更新与迁移；
6. 资料条目的来源、可见性与信息边界；
7. 安全检索与有界上下文投影；
8. 资料引用与当局游戏正式定义的边界；
9. Creator 创建 / 导入 / 引用 / 提取资料工作流；
10. “我的资产库”、Bundle、导入导出与游戏创建中的资料库关系；
11. 汉末三国历史与时代资料库真实首个消费者验证；
12. 穿越与系统“历史辅助”真实消费验证。

---

## 15. 禁止事项

不得：

- 因新增资料库而把产品主资产改成四类并列；
- 把资料库当作第二世界包；
- 把资料库条目直接当局内状态；
- 把源资料库更新静默覆盖现有游戏现实；
- 把绑定资料库整库加入模型上下文；
- 把资料库存在等价为玩家知道；
- 把历史参照当成未来必发生事件；
- 把世界专属时代资料继续伪装成第二套通用核心；
- 在三类主资产闭环完成前，为资料库修改首轮 Creator 主流程；
- 在三类主资产闭环完成前，为资料库扩大 G9-03 / G9-04 首轮协议和适配范围；
- 为了“以后反正要做”提前实现资料索引、检索、绑定或独立管理器。

---

## 16. 当前冻结结论

```text
三类主资产
= 世界包 + 角色卡 + 拓展包

资料库
= 资料资源层
= 已批准长期方向
= 后置增量功能

当前资料库实现状态
= DEFERRED

当前首要资产开发对象
= 世界包 / 角色卡 / 拓展包纵向闭环

资料库开发解锁条件
= GATE-LIB-01..06 全部 PASS

G9-02
= 不扩项

G9-03
= 只冻结三类主资产首轮协议

G9-04
= 只实现三类主资产首轮适配 / 编译 / 绑定

G9-05 Creator
= 先完成三类主资产基础创作链

资料库正式开发阶段
= 在“我的资产库 → 创建游戏 → 完整游玩”三类主资产闭环 PASS 后再确定编号并启动
```

> **先证明三类主资产从创作、资产库、组合、创建游戏到完整游玩真正跑通，再增加资料库。资料库是建立在成熟资产生态之上的增量能力，不是资产生态首轮成立的前置条件。**
