## 3. 进入 G9 前唯一必须完成的 G8 技术收口

### P0｜Legacy Creation 双轨退休 + Asset-Ready Convergence Audit

当前正式 Product UI 已只使用 Creation Project，但 production 仍保留旧 One Draft / Five Sections 路径，包括：

- legacy `GameCreationDraft` / `GAME_CREATION_SECTIONS` 等旧合同；
- `ProductFoundationClient` 中旧 Draft methods；
- `/api/product/new-game/drafts...` HTTP routes；
- GameCreationPublicApi 的旧 Draft mutation / generate / create path；
- 只为旧路径存在的 obsolete tests / adapters。

这不是当前玩家体验 blocker，但它是 **G9 架构 blocker**。

原因：

> G9 会正式接入 `External Asset → asset-spec Validation → New Game Asset Adapter → Runtime Definition → Game Instance`。如果 New Game / Creation 同时存在两个 production authority path，未来 Asset Adapter、Expansion Creation Contribution 和 Creator integration 会面临错误接线与永久兼容负担。

进入 G9 前必须：

1. 确认无真实外部兼容义务；
2. 删除 production legacy Draft / Five Sections 路径；
3. 保留必要历史证据，但不保留双轨运行入口；
4. 正式 Product New Game 唯一 authority = Creation Project；
5. 重跑 Creation / G8 / full regression；
6. 做一次 Asset-Ready Convergence Audit，确认 G9 只能依赖 current Contract。

完成后即可结束 G8 技术收口并进入 G9。

## 6. 为什么可以延后而不破坏原路线

原路线要求 G8 先建立可长期使用、asset-ready / runtime-extensible 的 Player Product UI，再进入 G9。

当前已经证明：

- 首页 / 游戏库 / 创建 / Session 主路径成立；
- Real DeepSeek Turn 已在 G8 前后持续成立；
- Runtime-extensible UI Host 已成立；
- Creation Contribution Host 已成立；
- API Settings / no-key startup 成立；
- 创建 → Game Instance 真人路径成立。

而 Save Center polish、Undo、多动作、Preview、Semantic Review、完整响应式等不会改变 G9 的核心边界：

```text
External Asset
→ tavern-asset-spec Validation
→ New Game Asset Adapter
→ Runtime Definition
→ Game Instance
→ Runtime UI Contribution
```

因此继续把这些体验增强全部串行放在 G9 前，会造成不必要的关键路径阻塞。

## 7. G9 的第一步仍保持原路线，不允许抢跑

完成 Legacy Retirement + Asset-Ready Audit 后，G9 **第一项工作不是直接写 asset-spec vNext，也不是直接导入资产**。

必须先做：

> **tavern-asset-spec + tavern-creator Compatibility Audit**

分类现有能力：

- A｜纯领域协议：保留；
- B｜概念正确、旧 Game Adapter 失效：保留协议，重写新版 Adapter；
- C｜被旧游戏实现污染：才进入正式协议升级。

不得因为用户希望尽快进入资产生态，就跳过 Compatibility Audit 或直接从零发明 vNext。
