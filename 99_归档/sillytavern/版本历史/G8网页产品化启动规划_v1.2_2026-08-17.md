## 5. Runtime-extensible UI 产品原则

Core Permanent World Surfaces 永久具现：

```text
人物｜地图｜物品｜信息｜目标
```

Host 至少支持九类落点：

1. Player Status；
2. Player Character Detail；
3. Entity Detail；
4. Core Surface Contribution；
5. Map Overlay；
6. Narrative Contextual；
7. Global Notice / Alert；
8. Game Creation / Settings Contribution；
9. Extension Surface。

同一个一级 Extension Surface 只能有一个 Owner。两个独立 Definition 同时 owns 同一 Surface时，创建游戏前判定 INCOMPATIBLE。

创作者明确要求独立一级 Surface 时，未来 Creator 应把自然语言意图编译成结构化 Ownership Request；正式 Runtime 不重复 NLP 猜测。

玩家拥有一级 Surface 最终显示顺序。排序属于 UI Preference，不属于 Game State / Formal Turn / Snapshot world authority。

Extension Surface 可以拥有受控 secondary View / Section；Host 渲染；禁止 arbitrary JS / React / DOM / eval / CSS injection。

## 9. Git Integration / Push / Independent Review

SillyTavern 当前采用项目级：

> **Executor-owned Git Integration。**

默认规则：

- Grok 完成 UI / Frontend task → Grok 对自己的 task-owned diff 运行 Gate、精确 stage、commit、push；
- Codex 完成 Runtime / Contract / Data / Provider task → Codex 对自己的 task-owned diff 运行 Gate、精确 stage、commit、push；
- Codex 仅在跨 Owner 集成、来源不明 dirty diff、remote conflict、复杂迁移或高风险仓库操作时担任专门 Integration Owner；
- 不再要求 Codex 为已经完成且通过 Gate 的 Grok task 做纯“代提交 / 代 push”。

所有 Executor 在 push 前必须：

```text
git branch --show-current
git rev-parse HEAD
git status --short
git diff --check
git fetch origin
```

并遵守：

- 只 stage task-owned 文件；
- 禁止 `git add .` / `git add -A`；
- 保护 pre-existing dirty / untracked；
- remote ahead / diverged / push rejected → `BLOCKED`；
- 不得自动 pull / merge / rebase / force push / reset --hard / clean / stash；
- Gate PASS 后才允许 fast-forward push；
- push 后 fetch 并确认正常情况下 `local HEAD == origin/main`。

独立审核默认采用 **GitHub-first Review**：

- Reviewer 直接读取正式远端 commit / exact-SHA files / tests / CI；
- Review ZIP 不再是普通任务必需交付物；
- 只有 Windows Launcher、真实 DeepSeek、本地 SQLite、fault injection 等 GitHub 无法证明的 Gate，才要求 supplemental evidence；
- `Push success != Independent Review PASS`。
