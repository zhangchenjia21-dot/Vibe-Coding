## 9. G9-03｜统一资产 / 资料资源协议冻结

只有 02C breadth 与 G9-02 Integrated Closure 全部 PASS 后才能冻结 external asset/resource contract。

### 三类主资产

必须覆盖：

- 身份 / 版本 / 完整性；
- source → local binding；
- immutable / evolvable / private policy；
- Owner / namespace；
- dependency / conditional / handoff / contribution；
- package / feature / module activation；
- routing / context contract；
- UI declaration；
- materialization / mutation eligibility；
- runtime binding metadata；
- compatibility / migration；
- Manifest / Bundle relationship。

### 资料库

同批冻结：

- 资料库源身份 / 版本 / 完整性；
- 条目稳定身份 / 来源；
- 世界包、角色卡、拓展包对资料库的引用；
- 世界包绑定 `0..N` 资料库的语义；
- 默认 / 推荐 / 可选资料关系；
- 独立 / 内嵌 / 引用的表达；
- 资料可见性 / 信息边界；
- 资料引用与当局游戏正式定义的边界；
- Bundle / Manifest / import / export 关系；
- 兼容 / 更新 / 迁移基础语义；
- 有界检索所需最小声明能力。

G9-03 不冻结任意查询 DSL，也不因为协议完成而授权资料库产品功能。

`tavern-asset` 的资料资源层语义应在这一批同步收口，避免语义治理与机器协议分叉。

## 14. 时序原则

> **协议一次设计完整，产品仍按主次分期。**

具体就是：

```text
世界包 / 角色卡 / 拓展包 / 资料库
→ 协议同批

世界包 / 角色卡 / 拓展包
→ Creator + 我的资产库 + 创建游戏 + 完整游玩先完成

资料库
→ Creator + 游戏本体 + Runtime 功能后置增量
```

这样既避免未来为资料库被迫整体升版协议，也不让资料库拖慢三类主资产成为成熟可玩产品。
