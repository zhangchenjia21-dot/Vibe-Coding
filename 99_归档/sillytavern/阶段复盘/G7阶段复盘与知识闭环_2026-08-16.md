## 3. 最大返工

最大返工是 **IdempotencyKey 的业务身份定义**。

被推翻的假设：

> 数据库有 `(gameId, idempotencyKey)` 唯一约束，就足以证明业务幂等。

新结论：

```text
logical submission identity
=
gameId
+ idempotencyKey
+ expectedRevision
+ canonical playerInput
```

不同 logical submission 复用同一 key 必须在副作用前 fail closed。

## 4. 第二个被推翻的假设

原 UAT 方案假设：

> “提交后马上刷新”可以自然覆盖 Recoverable 路径。

实际证明它依赖刷新时机与内部 execution stage 的竞速。

后续规则：

> 不再要求项目所有者用精确刷新、断网或 kill 时机命中内部状态窗口；窄窗口由 deterministic fault injection 验证。
