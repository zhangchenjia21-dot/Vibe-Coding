# G8 阶段内核心文件与 Skill 增量更新说明｜第二版经验复盘

## 1. 触发

项目所有者真实 Stage UAT 暴露：

- Engineering Exit Gate PASS 后，真实 AI-created world 仍可能为空壳；
- Rich Fixture 掩盖 Creation → Runtime 的内容缺口；
- Narrative 可见 affordance 与 authoritative Runtime referent 不一致；
- Contract / DTO / UI slot 存在被误判为真实能力完成；
- Bounded Context 被错误做成 Starved Context；
- 长期世界缺少 Source Asset / Game-local Canonical Asset / Runtime State 三层模型；
- 对“模型不能越权”的强调一度掩盖“模型必须能通过正式边界创造并演化真实世界内容”。

这些发现具有跨项目复用价值，因此从聊天反思升级为正式项目经验与通用 Skill。

## 6. 不得恢复的错误解释

以后不得再用：

- “测试都通过，所以游戏已经可玩”；
- “Contract 有，所以能力已完成”；
- “Fixture 有 NPC，所以 Creation 出来的游戏也有 NPC”；
- “Bounded Context 就应尽量少给信息”；
- “模型不能直接越权，所以模型不应写入任何 canonical content”；
- “Source Asset 不可变，所以一局游戏中的角色与世界定义也不可演化”；
- “HTTP 200 / DTO 一致，所以跨层产品语义一定一致”；
- “Stage UAT 只需要在工程全部完成后做一次”。
