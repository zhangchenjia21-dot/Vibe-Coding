# 18｜酒馆游戏：资料库资源层与世界创作集成裁定 v1.2

> [!abstract] 核心裁定
> 酒馆游戏继续保留 **世界包 / 角色卡 / 拓展包** 三类主资产架构；“资料库”定义为可独立复用、可被主资产绑定和按需检索的 **资料资源层**，不是第四类并列主资产。
>
> v1.2 对 v1.1 的时序作重要修正：**资料库的协议层不延后。资料库应与世界包、角色卡、拓展包在同一轮资产协议冻结中完成身份、版本、绑定、引用、信息边界、组合与导入导出关系的统一设计，以避免未来为了加入资料库再次升级整套资产协议。**
>
> 真正后置的是资料库的产品功能实现：Creator 资料创作界面、“我的资产库”资料库管理、创建游戏中的资料库选择 / 绑定、运行时资料检索与历史辅助等，仍必须等三类主资产纵向产品闭环完成后再开发。
>
> 正式冻结：**协议同批，功能后置；资料库不是局内正式状态，也不是整库上下文。**

---

## 0. 三类主资产不变，新增的是资料资源层

当前三类主资产继续承担稳定分权：

```text
世界包
= 世界身份 / 世界规则 / 地理社会框架 / T0 开局事实 / 默认组合

角色卡
= 重要人物定义 / 人格 / 决策逻辑 / 初始人物证据

拓展包
= 可复用或世界专属的机制 / 领域语义 / 玩法能力
```

大型时代、历史、制度、研究和设定资料不适合无限塞入世界包，也不应伪装成拓展包机制，因此长期架构增加：

```text
三类主资产
├─ 世界包
├─ 角色卡
└─ 拓展包

资料资源层
└─ 资料库
```

资料库是可被主资产引用的资料资源，不改变三类主资产作为游戏创建主资产的产品定位。

---

## 1. 资料库的唯一定位

资料库回答：

> **“有哪些长期可复用、可检索、可引用，但不应直接成为当前局内正式状态的大量资料？”**

典型内容：

- 历史与时代背景；
- 政治制度、官制、军制、经济制度、社会文化；
- 地理、地名、区域背景；
- 技术、宗教、学术、行业知识；
- 原历史事件与人物轨迹；
- 史料来源、争议与不同版本；
- 世界创作术语和大型设定解释；
- 可供世界包 / 角色卡 / 拓展包引用的定义来源与研究证据。

资料库不拥有当前人物、组织、政治、经济、战争、任务、关系、玩家知识或正式结果状态。

---

## 2. 世界包与资料库不是同一种上下文来源

```text
世界包
= 世界根来源
= 世界身份与基础语义锚点

资料库
= 参考资料来源
= 大量按需检索的参考内容
```

资料库长期必须遵守：

```text
已绑定资料库
!= 当前运行相关
!= 当前模型可见
```

以及：

```text
资料库包含某事实
!= 玩家知道该事实
!= 当前模型应该看到该事实
```

整库内容不得因为被绑定就进入模型上下文。

---

## 3. 资料库未来在游戏中的三类价值

### 3.1 世界定义 / 初始化参考

```text
资料库条目
↓ 创作 / 组合引用
正式领域定义
↓
当局游戏定义 / 状态
```

因此：

```text
资料库引用
!= 当局游戏正式定义
!= 局内正式状态
```

### 3.2 模型按需参考

未来运行链：

```text
当前输入 / 当前职责
+
当前正式锚点
↓
确认需要某类资料
↓
从本局绑定资料库检索相关条目
↓
执行信息边界 / 玩家知识边界过滤
↓
生成最小充分资料切片
↓
与当前必要正式状态有界组合
↓
模型
```

禁止：

```text
整个资料库
→ 每回合上下文
```

### 3.3 Creator / AI 创作辅助

未来 Creator 可以用资料库检索世界背景、生成时代一致内容、检查设定冲突、整理大量笔记并提取为独立资料库。

这一项属于后置产品能力，不因为协议先冻结就提前开发 UI。

---

## 4. 汉末三国历史参照与穿越玩法分权

长期目标保持：

```text
汉末三国历史与时代资料
→ 世界专属资料库

原历史参考 / 关键前提 / 史料 / 争议
→ 资料库中的历史参照部分

当前正式世界状态
→ 各正式事实拥有者 / Runtime

穿越与系统：历史辅助
→ 读取经过授权的历史参照资料
→ 不拥有原历史资料本身
```

穿越者可以利用原历史知识，但“有没有穿越者”不决定资料是否存在。

---

## 5. 世界专属政治 / 经济 / 战争资料的长期归宿

Shared Foundation 完成后，世界专属层不得为了旧资产结构继续维护第二套政治 / 经济 / 战争机制。

汉末三国长期目标：

```text
政治机制
→ 通用政治核心

经济机制
→ 通用经济核心

战争机制
→ 通用战争核心

汉末官制 / 政治文化 / 时代制度
汉末财赋 / 屯田 / 生产背景
汉末军制 / 兵种 / 战争环境
原历史人物与事件参照
→ 汉末三国历史与时代资料库
```

本节描述迁移终态，不等于当前授权资料库产品功能开发。

---

## 6. v1.2 核心时序：协议同批，功能后置

必须永久区分：

```text
资料库协议完成
!= 资料库产品功能实现
```

### 协议层

资料库协议与三类主资产在同一资产协议批次完成。

原因：

1. 资料库与世界包、角色卡、拓展包存在长期引用 / 绑定关系；
2. Bundle / Manifest / 导入导出结构需要预留统一关系；
3. 若先冻结仅三类资产的协议，未来增加资料库可能迫使整个协议再升版；
4. 资料库协议本身相对轻量，当前已拥有足够清晰的语义边界；
5. 同批设计可以一次处理身份、版本、引用、可见性和组合一致性。

### 产品实现层

以下全部延后：

- Creator 资料库创建 / 编辑 / AI 整理 / 提取；
- “我的资产库”资料库管理；
- 创建游戏时绑定 / 增删资料库；
- 运行时资料库索引与检索；
- 资料条目进入模型上下文的真实 Provider；
- 汉末三国历史与时代资料库正式制作与导入；
- `穿越与系统` 历史辅助真实消费。

---

## 7. G9-03｜统一资产 / 资源协议冻结

G9-03 在三类主资产协议之外，**同批冻结资料库协议**。

至少需要处理资料库的：

1. 源身份、版本与完整性；
2. 与世界包 / 角色卡 / 拓展包的引用关系；
3. 世界包绑定 `0..N` 资料库的语义；
4. 默认 / 推荐 / 可选资料组合；
5. 独立 / 内嵌 / 引用的机器表达；
6. 条目稳定身份与来源；
7. 可见性 / 信息边界元数据；
8. 资料引用与当局游戏正式定义的边界；
9. Bundle / Manifest / import / export 中的关系；
10. 版本兼容、更新与迁移的基础语义；
11. 有界检索所需的最小声明能力，但**不冻结任意查询 DSL**；
12. Creator 与游戏本体未来实现所需的最小协议挂点，但不实现界面。

同时同步 `tavern-asset` 的资料资源层语义，使资产创作治理与机器协议使用同一套身份 / 分权概念。

---

## 8. G9-04｜协议验证可以做，产品功能不能提前做

为了避免资料库协议成为只写不验的纸面协议，G9-04 可以包含**最小协议验证**：

```text
资料库协议样本
→ parse
→ validate
→ serialize / round-trip
→ 与世界包引用关系校验
```

允许：

- 资料库样本能被解析；
- 身份 / 版本 / 引用 / 可见性字段能被校验；
- 世界包引用资料库的协议关系能通过静态校验；
- 导入导出格式的结构往返不丢失协议数据。

明确不允许借机提前实现：

- “我的资产库”资料库页面；
- 新游戏创建时的资料库选择；
- 当局游戏资料库绑定生命周期；
- 运行时索引 / 语义检索；
- 模型上下文资料 Provider；
- Creator 资料库编辑器。

因此：

> **G9-04 对资料库只证明协议可实现，不交付资料库产品功能。**

## 9. Creator 与游戏本体的资料库部分仍然后置

长期产品方向保持：

### 创建游戏

```text
创建游戏
↓
选择世界包
↓
世界包详情 / 组合
└─ 世界资料
   ├─ 已绑定资料库
   ├─ 推荐资料库
   └─ 高级：添加 / 移除兼容资料库
```

普通玩家不增加强制“第四步：选择资料库”。

### Creator

```text
世界包
→ 资料与参考
→ 创建 / 导入 / AI 整理 / 引用 / 提取为独立资料库
```

这些界面与工作流不纳入 G9-05 三类主资产 Creator 首轮闭环。

## 10. 资料库产品功能开发前置门槛

资料库的**产品功能实现**只有在以下条件全部 PASS 后才启动。

### GATE-LIB-01｜统一协议已经完成

世界包、角色卡、拓展包、资料库的统一协议已经冻结并通过最小解析 / 校验 / 往返验证。

### GATE-LIB-02｜三类主资产真实适配与当局游戏绑定完成

世界包、角色卡、拓展包能够从“我的资产库”进入新游戏并形成稳定当局游戏定义和运行状态。

### GATE-LIB-03｜Creator 三类主资产基础创作链完成

三类主资产至少可创建、编辑、AI 辅助、校验、保存、导入导出并回到“我的资产库”继续使用。

### GATE-LIB-04｜“我的资产库 → 创建游戏”主链完成

```text
我的资产库
→ 管理三类主资产
→ 创建新游戏
→ 选择世界包
→ 组合角色卡与拓展包
→ 组合校验
→ 正式创建游戏
```

### GATE-LIB-05｜真实资产组合完整游玩 PASS

```text
三类主资产创作 / 导入
→ 我的资产库
→ 创建新游戏
→ 初始化
→ 正常游玩
→ 领域机制与上下文工作
→ Save / Continue / Restore / Branch / Recovery
→ 可持续完整游玩
```

### GATE-LIB-06｜主资产产品问题已先收口

若三类主资产仍存在阻塞性的 Creator、组合、导入、创建游戏或运行问题，优先修主链；资料库产品功能不得成为绕开主链问题的新工作面。

## 14. 禁止事项

不得：

- 因资料库而把产品主资产改成四类并列；
- 把资料库当作第二世界包；
- 把资料库条目直接当局内状态；
- 把源资料库更新静默覆盖现有游戏现实；
- 把绑定资料库整库加入模型上下文；
- 把资料库存在等价为玩家知道；
- 把历史参照当成未来必发生事件；
- 把世界专属时代资料继续伪装成第二套通用核心；
- 把“协议同批”偷换成“Creator / 游戏功能同批”；
- 在三类主资产产品闭环完成前实现资料库管理、检索、绑定 UI；
- 为资料库设计任意脚本、查询 DSL 或未验证的运行时万能接口。
