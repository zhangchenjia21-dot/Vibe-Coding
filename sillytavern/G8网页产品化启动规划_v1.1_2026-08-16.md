## 5. Runtime-extensible UI 产品原则

Core Permanent World Surfaces 永久具现：

```text
人物｜地图｜物品｜信息｜目标
```

Host 至少支持九类落点：

1. Player Status；
2. Player Character Detail；
3. Entity Detail；
4. Core Surface Contribution；
5. Map Overlay；
6. Narrative Contextual；
7. Global Notice / Alert；
8. Game Creation / Settings Contribution；
9. Extension Surface。

同一个一级 Extension Surface 只能有一个 Owner。两个独立 Definition 同时 owns 同一 Surface时，创建游戏前判定 INCOMPATIBLE。

创作者明确要求独立一级 Surface 时，未来 Creator 应把自然语言意图编译成结构化 Ownership Request；正式 Runtime 不重复 NLP 猜测。

玩家拥有一级 Surface 最终显示顺序。排序属于 UI Preference，不属于 Game State / Formal Turn / Snapshot world authority。

Extension Surface 可以拥有受控 secondary View / Section；Host 渲染；禁止 arbitrary JS / React / DOM / eval / CSS injection。

## 6. 正式 Session 产品原则

- 中央 Narrative 是视觉中心；
- Desktop 三栏处于一个统一布局；
- Center 到左右栏的视觉间距一致；
- Narrative Timeline 独立滚动；
- Left / Right 各自拥有内部滚动；
- 长聊天不让整页 document scroll 把左右栏滚走；
- Top Bar 保持可见；
- 资料条目使用紧凑 Card / Section；
- 窄屏 Narrative-first；
- Product UI 与 Engineering Playtest Shell 分离。
