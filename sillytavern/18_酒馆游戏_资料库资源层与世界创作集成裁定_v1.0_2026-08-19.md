# 18｜酒馆游戏：资料库资源层与世界创作集成裁定 v1.0

> [!abstract] 核心裁定
> 酒馆游戏继续保留 **世界包 / 角色卡 / 拓展包** 三类主资产架构；新增的“资料库”不成为第四类并列主资产，而定义为一层可独立复用、可被主资产绑定和按需检索的 **资料资源层**。
>
> 世界包仍是“这一局是什么世界”的根资产；资料库回答“关于这个世界或某个领域，有哪些大量背景、时代、历史、制度、研究与参考资料可以在创作、初始化和运行时按需使用”。
>
> 正式冻结：**资料库不是 Runtime State，也不是整库 Prompt。**

---

## 0. 为什么需要资料库，但不改成四类主资产

当前三类主资产已经形成稳定分权：

```text
世界包
= 世界身份 / 世界规则 / 地理社会框架 / T0 开局事实 / 默认组合

角色卡
= 重要人物 Definition / 人格 / 决策逻辑 / 初始人物证据

拓展包
= 可复用或世界专属的机制 / 领域语义 / 玩法能力
```

大型时代资料、历史资料、制度资料、研究资料若全部塞进世界包，会造成：

- 世界包正文无限膨胀；
- 多世界重复维护同一时代资料；
- 普通 Turn 上下文被误认为需要整包常驻；
- Creator 无法区分“世界根定义”和“大量可检索参考资料”；
- 原历史参照、史料来源、争议记载等内容被误当成当前世界状态。

因此新增资料资源层，但不改变三类主资产的产品定位。

正式关系：

```text
Primary Assets
├─ World Pack
├─ Character Card
└─ Expansion Pack

Reference Resource Layer
└─ Library / 资料库
```

---

## 1. 资料库的唯一定位

资料库回答：

> **“有哪些长期可复用、可检索、可引用，但不应直接成为当前局内正式状态的大量资料？”**

典型内容包括：

- 历史与时代背景；
- 政治制度资料；
- 官制、军制、经济制度、社会文化资料；
- 地理、地名、区域背景；
- 技术、宗教、学术、行业知识；
- 原历史事件与人物轨迹；
- 史料来源、争议、不同版本；
- 世界创作中的术语、设定解释和大型参考条目；
- 可供世界包 / 角色卡 / 拓展包引用的定义来源与研究证据。

资料库不拥有：

- 当前人物状态；
- 当前组织成员关系；
- 当前政治控制；
- 当前经济库存；
- 当前战争结果；
- 当前任务；
- 当前关系；
- 当前玩家知识真相；
- Formal Outcome / Atomic Commit。

---

## 2. 世界包与资料库不是同一种上下文来源

正式区分：

```text
World Pack
= Root World Source
= 世界根身份与基础语义锚点

Library
= Reference Resource Source
= 大量按需检索的参考内容
```

世界包可以向 Runtime 提供少量高价值根语义，例如：

- 当前世界是什么；
- 当前时代与基调；
- 核心世界规则；
- 当前 T0 / 场景锚点；
- 当前组合中有哪些正式资产。

资料库默认采用：

```text
Bound Library
!= Current Runtime Relevant
!= Current Model Visible
```

整库内容不得因为“本局绑定了该资料库”就进入模型上下文。

---

## 3. 资料库如何在 Runtime 发挥作用

资料库主要有三类运行价值。

### 3.1 作为世界定义 / 初始化的参考来源

Creator 或 World Pack 可以引用资料条目建立正式世界定义，例如：

```text
资料库：汉末“州牧”制度资料
↓
World composition / authoring
↓
ORG 领域建立本局正式职位 Definition
↓
具体人物任职进入 Game-local / Runtime State
```

因此：

```text
Library Reference
!= Game-local Canonical Definition
!= Runtime State
```

资料只能作为来源、证据和定义输入，不能绕过正式 Owner 直接写入状态。

### 3.2 作为模型按需参考上下文

正确链：

```text
当前玩家输入 / 当前模型职责
+
当前 authoritative anchors
↓
确认需要某类参考资料
↓
在本局已绑定且兼容的资料库中检索相关条目
↓
执行信息边界 / 玩家知识边界过滤
↓
生成最小充分资料切片
↓
与当前必要 Owner Projection 有界组合
↓
Model
```

禁止：

```text
Whole Library
→ every Turn Prompt
```

### 3.3 作为 Creator / AI 创作辅助来源

Creator 可以使用资料库：

- 检索世界背景；
- 辅助生成 World Pack 内容；
- 生成角色卡的时代一致背景；
- 为拓展包提供世界专属定义；
- 检查创作内容与已有资料是否冲突；
- 将大量创作笔记整理、去重并提取为独立资料库。

Creator AI 使用资料库不等于资料自动进入最终 Source Asset；作者仍应确认正式创作结果。

---

## 4. 资料库与玩家知识必须分离

正式冻结：

```text
Library Contains Fact
!= Player Knows Fact
```

资料库可以包含：

- 作者可见但玩家未知的历史真相；
- Runtime 可用于一致性判断的隐藏参考；
- 当前世界公开常识；
- 穿越者可能知道的原历史；
- 只有特定角色知道的专业知识来源。

具体内容能否进入玩家可见模型上下文，必须经过当前游戏的信息边界、角色知识或产品权限判断。

因此资料库不能成为绕过隐藏信息规则的“后台全知 Prompt”。

---

## 5. 历史参照与穿越玩法的正式分权

汉末三国案例正式采用：

```text
汉末三国历史与时代资料
→ 世界专属资料库

原历史参考 / 关键前提 / 史料 / 争议
→ 资料库中的历史参照部分

当前正式世界状态
→ 各 Canonical Owner / Runtime

穿越与系统：历史辅助
→ 读取经过授权的历史参照资料
→ 不拥有原历史资料本身
```

所以：

```text
Historical Reference Data
!= Traveler Feature
!= Current History
```

穿越者可以使用原历史知识，但“有没有穿越者”不决定资料是否存在。

---

## 6. 世界专属政治 / 经济 / 战争资料的归宿

Shared Foundation 完成后，世界专属层不得为了旧资产结构继续维护第二套政治 / 经济 / 战争机制。

例如汉末三国：

```text
政治机制
→ EP-POLITICS-CORE

经济机制
→ future EP-ECONOMY-CORE

战争机制
→ future EP-WAR-CORE

汉末官制 / 政治文化 / 时代制度
汉末财赋 / 屯田 / 生产背景
汉末军制 / 兵种 / 战争环境
原历史人物与事件参照
→ 汉末三国历史与时代资料库
```

只有真正无法由“通用 Core + 世界包 + 资料库”表达、且具备独立运行价值的机制，才继续保留世界专属 Expansion。

---

## 7. 创建游戏流程

创建游戏的主流程仍然以世界包为入口。

推荐产品语义：

```text
创建游戏
↓
选择 World Pack
↓
世界包详情 / 组合
├─ 世界简介
├─ 角色 / 主角选择
├─ 默认 / 推荐 Expansion
└─ 世界资料
   ├─ 已绑定资料库
   ├─ 推荐资料库
   └─ 高级：添加 / 移除其它兼容资料库
```

正式冻结：

- 普通玩家不需要经历一个新的“第四步：选择资料库”；
- World Pack 可以语义上绑定 0..N 个资料库；
- 世界包可以声明默认 / 推荐资料组合；
- 高级自定义组合可以允许用户增删兼容资料库；
- 是否物理内嵌、独立打包、远程引用，等待 G9-03 / G9-04 冻结。

---

## 8. Creator 产品入口

Creator 中资料库与 World Pack **产品上紧密结合，架构上保持可独立复用**。

推荐 World Pack Creator：

```text
世界包
├─ 世界概览
├─ 世界规则与基调
├─ 地理 / 社会结构
├─ 开局 / T0
├─ 资料与参考
│  ├─ 创建资料
│  ├─ 导入资料
│  ├─ AI 整理 / 切分 / 去重
│  ├─ 引用已有资料库
│  └─ 将大型资料提取为独立资料库
├─ Opening Scenario（若未来启用）
└─ 资产组合
```

作者初期可以把资料当作“世界包中的资料与参考”直接创作；当内容规模、复用需求或维护生命周期足够大时，再提取成独立资料库。

这实现：

> **逻辑上紧密结合，物理上允许独立。**

未来可以提供独立资料库管理器，但它不是普通 World Pack 创作流程的前置要求。

---

## 9. 跨主资产引用

资料库最常见的 Owner / Entry Point 是 World Pack，但长期允许：

```text
World Pack → Library
Character Card → Library reference
Expansion Pack → Library reference
```

用途例如：

- 角色卡引用某时代 / 宗门 / 家族背景资料；
- 魔法 Expansion 引用大型术语 / 理论资料；
- 多个 World Pack 共享同一时代资料库。

但引用不等于复制；资料库内容仍保持自己的来源与版本身份。

---

## 10. 版本、绑定与现有游戏稳定性

正式产品语义：

```text
Source Library
→ Game binding / selected revision
→ JIT reference projection
```

Source Library 更新不得静默改写：

- 已有 Game-local Definition；
- 当前 Runtime State；
- 已发生 Event；
- 玩家已知事实。

已有游戏必须有稳定的资料版本 / 修订绑定语义；未来是否允许显式更新、重绑或迁移，由 G9-03 / G9-04 冻结。

当前不冻结 exact hash / wire / version field。

---

## 11. 上下文规模原则

新增正式原则：

```text
Library Size ↑↑↑
ordinary unrelated Turn context ≈ stable
```

以及：

```text
Bound Library Count ↑↑↑
unrelated Turn model-visible reference slices ≈ 0
```

目标查询才按需取当前最小充分资料。

例如 10,000 条汉末资料存在时，玩家“去客栈吃饭”不应读取官制 / 战役 / 屯田资料；玩家询问“州牧和刺史有什么区别”时才读取对应条目。

资料库检索与大型关系图同样必须遵守：

- 有界；
- 不饥饿；
- 保留来源；
- 信息安全；
- 不递归全文展开。

但本轮不要求 02C 实现真实资料库检索 Provider。

## 13. G9-03 Freeze Gate 新增输入

G9-03 冻结 external asset / resource contract 时，必须显式处理资料资源层，至少决定：

1. 资料库 source identity / version / hash；
2. 世界包与 0..N 资料库的绑定关系；
3. 默认 / 推荐 / 可选资料组合语义；
4. 资料库独立 / 内嵌 / 引用的机器表达；
5. source → game binding / revision / update / migration；
6. 资料条目的来源 / 可见性 / 信息边界语义；
7. 资料检索 / 上下文投影的安全契约；
8. Library Reference 与 Game-local Canonical Definition 的边界；
9. Creator 创建 / 导入 / 引用 / 提取工作流所需最小机器能力；
10. Bundle / import / export 中资料库与三类主资产的关系。

当前仍禁止提前发明这些字段的最终 JSON 形状。

---

## 14. 禁止事项

不得：

- 因新增资料库而把产品主资产直接改成四类并列；
- 把资料库当作第二 World Pack；
- 把资料库条目直接当 Runtime State；
- 把 Source Library 更新静默覆盖现有游戏现实；
- 把绑定资料库整库加入 Prompt；
- 把资料库存在等价为玩家知道；
- 把 Historical Reference 当成未来必发生 Event；
- 把世界专属时代资料继续伪装成第二套 Generic Core；
- 为方便 Creator 强迫所有作者先学习独立资料库机器结构；
- 在 G9-03 前冻结 final schema / retrieval DSL / query language。

## 15. 当前冻结结论

```text
Primary Asset Architecture
= World Pack + Character Card + Expansion Pack

Reference Resource Layer
= Library / 资料库

World Pack
= root world asset

Library
= reusable / bindable / searchable reference resource

World Pack can bind
= 0..N Libraries

Creator main UX
= World Pack > 资料与参考

Game creation main UX
= World Pack first
+ World Pack 详情内管理世界资料

Runtime
= JIT bounded retrieval
!= whole-library prompt

Library truth
!= Game-local canonical truth
!= Runtime state
!= Player-known truth

G9-02C
= no scope expansion

G9-03
= must freeze resource-layer machine contract
```

> **资料库补充的是“世界与机制的知识来源层”，不是第四套游戏状态，也不是第四个强制主资产入口。**
