## 3.2 G9-02｜Runtime Asset Binding + Context Orchestration Foundation

**必须位于 asset-spec vNext Schema Freeze 之前。**

原因：第 15 号核心裁定已经改变 G9 Task DAG。Runtime 必须先用 internal handwritten profiles 证明以下链：

```text
Player Input
+
Current Game Enabled Expansion / Capability Directory
+
Minimal Current Scene Summary
↓
Router Model
↓
Immediate Expansion / Domain / Intent candidates
↓
Program Mechanical / Structural Validation
+
State-mandatory Augmentation
↓
Current Runtime Relevant Set
↓
JIT Bounded Runtime Projection
↓
Semantic / Resolution / Narrative consumers
```

Foundation 至少冻结并 vertical-proof：

- Routing Profile；
- Enabled Directory；
- Activation / No-load semantics；
- Minimal Read Set；
- Model-needed vs Program-owned logic；
- Output Candidate boundary；
- Handoff；
- Information Boundary；
- Context Cost / boundedness；
- Router unknown-ID / omission / over-selection behavior；
- state-mandatory augmentation。

此阶段只用 internal typed / handwritten profiles，不冻结外部资产 JSON Schema。

原则：

> **Runtime Context Orchestrator Before Asset Context Schema。**

Router 是 context selection / semantic routing，不是玩家动作白名单。

# 5. 当前工程原则

1. Single Authority。
2. Shared Foundation Before Consumers。
3. Host Before Protocol。
4. Runtime Context Orchestrator Before Asset Context Schema。
5. Declarative Structure ≠ Live Data Access。
6. Supersession Before Compatibility。
7. Dependency Graph != Context Inclusion Graph。
8. Program owns state / permission / RNG / resolution / commit / recovery。
9. Model role bounded to semantic interpretation / advisory / narrative。
10. Product UX 可按 personal / Alpha / Release 成熟度分级。
11. Push ≠ PASS；正式实现仍需 GitHub-first Independent Review。
