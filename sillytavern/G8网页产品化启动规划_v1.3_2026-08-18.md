## 3. 当前最优先：G8-WEB-04｜Final Host Convergence

状态：`ACTIVE / REQUIRED / NEXT`

当前 Host Foundation 已证明：

- Core 五 Surface；
- 9 类 Host Capability；
- Owner / Contributor；
- duplicate Owner fail closed；
- Extension Surface；
- secondary View；
- safe component vocabulary；
- controlled Action Intent；
- fixture / preview Product presentation；
- in-process reorder semantics。

但进入 G9 前仍必须完成正式 Convergence。

### 3.1 正式 Bootstrap

建立：

```text
handwritten typed Runtime UI Definition
→ Host Assembly
→ Real Product Bootstrap / Server
→ player-safe Product DTO
→ Formal Product UI
```

不能继续只靠 `?host=` preview / fixture 证明动态 UI。

### 3.2 声明结构与 Live Data 分离

冻结：

```text
Definition = 声明需要什么安全 UI 结构
Runtime / Projection = 产出当前 player-safe value
Host = 验证与渲染
```

禁止 asset/definition 持有 arbitrary state path / selector / expression / query DSL。

### 3.3 Creation Contribution 对齐

Host `game_creation_settings` 必须从旧 Five Sections 语言迁移到当前 Creation Project：

- expansion_settings；
- character；
- opening。

旧 `sectionId / required / playerEditable` + `GAME_CREATION_SECTIONS` adapter 不再作为未来 Host 事实源。

### 3.4 Contribution Source Identity

Host assembly 必须保留来源 Definition identity，形成内部 owner/source bridge，以支持 Creation Contribution active ↔ dormant。

### 3.5 Durable UI Preference

Surface Order 必须独立于 Game State / Save Snapshot，并能跨应用重启持久化。

Restore 不回滚 UI Preference；新增 Surface 保留旧玩家排序相对顺序并确定性插入。

### 3.6 Dynamic UI Vertical Proof

至少一个 live player-safe value 在 Formal Turn 后由 Runtime Projection 更新，同一 declarative contribution 自动显示新值；不得通过替换 fixture 冒充动态数据。

正式依据：

`14_酒馆游戏_G8_RuntimeExtensibleUI产品架构裁定_v1.1_2026-08-18.md`
