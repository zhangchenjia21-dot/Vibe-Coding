长期产品裁定：

1. 资料库是资料资源层，协议先完成、完整产品功能后置；
2. Creator 首版采用结构化主工作区 + AI 创作对话区 + 受控 Draft 编辑；
3. “我的资产库”顶层四入口固定为 Creator、世界包、角色卡、拓展包；
4. 外部创作稿由 AI 只整理能够明确确定且唯一映射的内容，不确定/冲突/缺失保持空白或原值；
5. Creator Draft、正式 Source Asset、本局实例、Runtime State 永久分层；
6. AI 的修改权来自用户当前任务级授权，不因为进入 Creator 就获得整份草稿默认写权限；
7. typed node 授权绑定精确语义种类 + 节点身份 + 操作族；Provider `unknown` 输出必须经 Program 完整运行时解析；
8. G9-02 / G9-03 / G9-04 / G9-05B 已关闭，下游 Creator 不重新建立第二套运行时、资产协议、草稿、正式资产库或发布事务；
9. World Creator 的高级编辑必须能完整表达 World Source 允许的 composition / dependency 语义，不用固定默认值冒充正式编辑能力；
10. World Creator 不暴露 Expansion-only `feature_conditional` dependency 语义；
11. Import continuation 只能按 formal target / exact identity 定位，不按显示标题或描述猜测；
12. Source 可发布不等于 catalog 语义已证明，相关修复必须补齐 `validateAssetCatalog()` 证据；
13. Character Creator 必须复用共享 Creator Core 和已验证的 Creator 产品模式，但工作区必须依据 Character schema 单独设计，禁止生搬 World-only composition；
14. Character Creator 的 `playerCharacterSupported` 是 Source 三态声明，不等于当前玩家角色选择或 Runtime materialization；
15. Character Source 创建、编辑、导入、发布、查看和新版本流程必须通过 No-Phantom Gate，不得产生当前位置、关系、知识、伤势、当前身份/阵营等 live state；
16. Character dependency 与 World 一样只暴露 `hard | optional | reference`，不暴露 Expansion-only `feature_conditional/sourceScope`；
17. Character `referenceSources` 只使用 exact ref，Library product 未授权前不做 fuzzy lookup / retrieval；
18. G9-05D Character Creator 收口后，优先实现【使用我的资产库】创建游戏，再实现 Expansion Creator；
19. 【使用我的资产库】只消费已发布 Source Asset exact snapshot；Creator Draft 不可直接进入 Game Manifest，也不可在建局时自动发布或临时转为 Source；
20. Expansion Creator 不是资产建局的前置条件；`TavernGameAssetManifestV1.expansions` 允许为空；
21. Source binding 不等于 semantic materialization；G9-04 hidden anchor 不能冒充可玩 World/Character；
22. G9-05E 新增共享 Asset Game Creation Core，先做 exact selection / dependency closure / deterministic materialization，再接产品 UI；
23. hard dependency 必须由当前 Manifest 中 exact selected snapshot 满足；stable ref 不自动解析 latest；
24. Character 资产进入本局时角色用途必须显式区分 `bound_only | opening_character | player_character`；只有 Final Create 明确指定的 opening/player 角色才物化；
25. 只有 `playerCharacterSupported=true` 的 Character Source 可以成为 Source-backed player；0 Character Source 时由玩家显式填写本局 player identity；
26. G9-05E 核心链 Provider calls = 0，No-Provider 也必须能从 published Source 创建可玩游戏；
27. Final Create 使用 Program-derived `createFingerprint`；成功响应丢失后允许原请求身份重放同一 game，不允许任意 stale revision 绕过 CAS；
28. Source-player chooser mode 与 exact Character selection 永久分离，进入列表不等于选中第一项；
29. 建局产品的 authoritative selection identity 永远是 `assetRef + assetType + version + contentHash`；同 stable ref 的 sibling version 不得继承 selected/role/enablement；
30. Compatibility Review 必须显示 Character exact version + role、Expansion exact version + enabled feature/module，让玩家在 Final Create 前看见实际 Manifest 选择事实；
31. Expansion Source `moduleRef` 与 Program `runtimeModuleRef` 永久分层；Creator 不得把 Source 声明身份冒充 Runtime module identity；
32. Expansion Program-owned refs（`runtimeModuleRef / config.schemaRef / projectionRef / hostCapability`）必须来自当前 Program Capability/Host truth，manual/import/AI 共用同一语义 gate；
33. Expansion Publish 与 Runtime activation 永久分离；Publish 只 append Source，不启用当前 game feature/module；
34. `publishing` recovery 在任何 Source append 前必须重新执行当前 Host Gate，Host 能力变化时 fail closed；
35. Expansion AI exact scope 必须覆盖 scalar/section/dependency/feature/module/UI surface/UI contribution，但只获得本任务明确授权节点；
36. 已存在正式语义 identity 对 AI 只读：`sectionRef / dependencyRef / featureRef / moduleRef / surfaceId / contributionRef`，共享 gate 同时覆盖 World `compositionRef` 与 Character `referenceRef`；
37. G9-05F 收口后不再继续增加主资产 Creator 类型，下一阶段必须优先证明 World + Character + Expansion 三类真实 published Source 的完整组合建局、运行、存档与恢复闭环。
