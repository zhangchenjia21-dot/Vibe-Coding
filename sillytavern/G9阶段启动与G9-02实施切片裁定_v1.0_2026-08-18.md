## 2. G9-02 为什么拆成三条内部 Slice

原 G9-02 同时覆盖 persistence、Game-local mutation、Expansion Host、Domain extensibility、Context Router，单任务 blast radius 过大。

因此保持同一阶段目标，但拆成：

```text
G9-02A Source Binding + Game-local Revision Foundation
↓
G9-02B Runtime Domain / Expansion Binding Host
↓
G9-02C Context Orchestration Foundation
↓
G9-02 Integrated Closure
↓
G9-03 asset-spec vNext
```

这不是新增生命周期阶段，而是降低深水区返工风险的 implementation slicing。

- Source Asset identity/version/hash 可绑定到单局；

```text
NO CHANGE / DO NOT INTERRUPT
```

## 4. G9-02B

建立 Runtime Domain / Expansion Host：

- package inclusion；
- feature/module activation；
- dependency availability；
- built-in domain module registration；
- extensible owner-typed canonical record / state；
- typed candidate / event / handoff extension seam；
- definition registry binding；
- G8 UI Host definition/contribution binding。

同时必须建立或保留 **Player-known Entity / Character Directory** 的正式 Runtime owner / projection seam：

```text
Current Scene Visible Characters
!=
Player-known Character Directory
```

People Surface 必须面向长期 player-known character records，而不是当前 Scene presence。角色离场后仍保留；未被玩家认识的 Game-local Character 不得泄露；Directory 中只能保存 player-known / last-known safe projection。

Asset 不提供 JS / callback / eval；Runtime built-in Domain Module 拥有代码和验证。
