---

## 1. 当前开发阶段裁定

当前项目仍处于项目所有者个人开发与架构成型阶段，不是面向外部玩家的 Alpha / Release。

因此，G8 退出条件必须区分：

1. **会改变 G9 asset-spec / Creator / Game Adapter 基础协议的前置能力**；
2. **只改善玩家产品体验、但底层权威语义已经成立的 Product UX**。

只有第 1 类继续阻塞 G9。

这不是删除第 2 类需求，而是移出当前关键路径。

---

## 2. G8-WEB-04｜Final Host Convergence：REQUIRED / NEXT

进入 G9 前必须关闭。

必须完成：

- 正式 Bootstrap 支持 typed handwritten Runtime UI Definitions，不再只证明 core-only Host；
- handwritten definitions 能走 `Host Assembly → Real Product Server → player-safe Product DTO → Formal Product UI`；
- 声明式动态 UI 的结构能力以正式纵向链证明，而不是只靠 `?host=` preview / fixture；
- Host `game_creation_settings` 与新 Creation Project 的 `expansion_settings / character / opening` Contribution 模型对齐；
- 旧 Five Sections Creation Contribution adapter 退休；
- Contribution source / owner identity 可追踪，并能桥接到 `ownerGameplayId` / 等价内部 owner；
- player-safe live contribution data/projection 边界冻结：Runtime / Adapter 产出安全 DTO，资产/声明不拥有任意 state path / expression engine；
- Surface Order UI Preference 独立于 Game State / Save Snapshot，并具备正式产品重启后的持久化行为；
- 新 Surface 插入保持玩家已有相对排序；Restore 不回滚 UI Preference；
- duplicate owner / invalid dependency / unsupported component / arbitrary frontend code 继续 fail closed；
- Creation Contribution active ↔ dormant 能与 gameplay enable/disable 正确衔接。

G8 只使用内部 handwritten typed definitions 验证，不开始 asset-spec / Creator machine schema。

---

## 3. G8-WEB-05｜Technical Migration Closure：REQUIRED

玩家主路径已 PASS，但进入 G9 前必须完成架构单轨化：

- 正式 New Game authority = Creation Project；
- 删除 production `GameCreationDraft / One Draft / Five Sections` 双轨；
- 删除 Product client legacy Draft methods；
- 删除 `/api/product/new-game/drafts...` routes；
- 删除 GameCreationPublicApi legacy Draft store / generation / create path；
- 迁移/删除 obsolete legacy tests；
- 保留 G9 仍需要的 `use_my_assets` product shell / asset-flow concept，但不得因为一个合法概念继续保留旧 Draft architecture。

完成后做 Asset-Ready Convergence Audit。

---

## 4. G8-WEB-06｜Save Center + Recovery / Error UX：DEFERRED / NON-BLOCKING

当前正式 Save Center 产品页尚未完整实现，但 G6 Save / Continue / Restore 与 G7 Crash / Resume / Recovery 的权威 Runtime 语义已经 PASS / CLOSED。

在个人开发阶段，暂不要求为了进入 G9 实现完整玩家产品入口。

后续 Alpha / Product 阶段补：

- Save Center；
- Create Save / Restore 浏览体验；
- Branch pending / committed result 的玩家化表达；
- Recovery / Error 的低工程术语 UX；
- 更完整的 Timeline / Archive 管理。

约束：不得因 UI 延后而改变或绕过 G6/G7 已冻结权威语义。

---

## 5. G8-WEB-07｜Correction / Undo / Re-input：DEFERRED / NON-BLOCKING

玩家可见撤回 / 重新输入属于重要产品能力，但不是当前 asset-spec / Creator 的结构前置。

底层未来实现必须建立在：

- G6 Restore；
- G7 exactly-once / idempotency；
- 不静默改写历史；
- 不把失败输入当成功 Turn。

当前个人开发阶段不阻塞 G9；进入 Alpha 前重新列为 required。

---

## 6. G8-WEB-08｜Controlled Multi-action：REQUIRED，但缩为 Core Semantic Vertical Slice

该能力继续留在 G9 前，因为它可能影响未来 Expansion Action Intent / Resolution capability 的基础边界。

但本阶段不做完整玩家产品功能，只完成最小核心语义：

- 支持少量顺序明确的多动作表达；
- 一个 Player Input 最终仍最多形成一个 Formal Turn；
- Program 拥有顺序、权限、时间推进与最终提交；
- no partial commit；
- 任一必要子动作失败时整体不产生部分世界提交；
- 不建设通用 Planner / workflow DSL；
- 不让模型拥有正式多步骤执行 authority；
- 用真实/fixture vertical proof 证明最小能力即可。

UI 只需足以验证，不要求产品 polish。

---

## 7. G8-WEB-09｜不再作为独立功能开发任务，改为 G8 Exit Gate

不再预设一轮大规模 responsive / accessibility 重构。

在 WEB-04、WEB-05 技术收口与 WEB-08 最小语义完成后，直接做一次阶段 Gate：

- 当前 Desktop 主路径无 blocker；
- 当前 narrow 关键路径无 blocker；
- keyboard / focus 无明显 blocker；
- Product E2E 覆盖当前必须能力；
- no-key / configured-key；
- Creation → Session；
- Host handwritten vertical proof；
- Controlled Multi-action vertical proof；
- G5–G7 regression；
- GitHub-first Final Review；
- 项目所有者一次 G8 Stage UAT。

只有发现 P0/P1 blocker 才创建修复任务。

完整 WCAG、所有设备像素级适配、高级动画与视觉 polish 后置到 G11 / Product Polish。
