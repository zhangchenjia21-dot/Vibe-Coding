# G9-05E｜使用我的资产库创建游戏｜产品与内部合同规格 v1.0

## 1. Outcome

G9-05E 把产品中长期保留但尚未接线的：

```text
创建新游戏
→ 使用我的资产库
```

从 placeholder 变成真实可用纵向。

首轮闭环：

```text
已发布 Source Asset exact snapshots
↓
用户明确选择本局资产与角色用途
↓
Program-owned selection / dependency / placement validation
↓
exact TavernGameAssetManifestV1
↓
确定性 Source → Game-local materialization
↓
existing G9-04 compileAssetBindingPlan()
↓
atomic SQLiteRuntimeStore.bootstrap()
↓
Session
↓
Save / Continue / Restore / Recovery
```

第一轮最低支持：

```text
1 exact published World
+
0..N exact published Characters
+
0..N exact published Expansions（可为空；不要求 Expansion Creator）
+
0 Library product selection
```

完成后，World / Character Creator 产出的正式 Source Asset 必须能够真实用于创建可玩的游戏，而不是只生成一个与所选资产无关的 Runtime fixture 再挂 lineage 标签。

## 3. Permanent Boundaries

继续保持：

```text
Creator Draft
!= Saved Source Asset
!= Game-local Canonical Instance
!= Runtime State
```

```text
Source binding
!= semantic materialization
```

```text
Character Source binding
!= Runtime Character
```

```text
Selection
!= Creation Commit
```

只有最终显式“创建游戏”动作可以启动 Game-local materialization 与 Runtime bootstrap。

禁止：

- Creator Draft 进入 Manifest；
- 建局时自动发布 Draft；
- 把 Draft 临时编译成 Source；
- 使用 display title / alias / filename 猜 `assetRef`；
- stable-ref-only 自动解析 latest version；
- 仅挂 hidden binding anchor 就声称 Source 内容已经形成可玩世界；
- 因 Character 被加入 Manifest 就自动给它当前位置、关系、知识、伤势、阵营或玩家控制权；
- 复制第二套 G9-04 binding compiler；
- 建立第二套 Runtime bootstrap；
- 在 G9-05E 内实现 Expansion Creator 或 Library 产品检索。

## 4. 为什么必须新增 Asset Game Creation Core

当前已有两条能力各自只解决一半问题：

### 4.1 AI-assisted Creation Project

已有：

```text
CreationProject
→ typed semantic materialization
→ RuntimeDefinition
→ atomic bootstrap
```

它的输入是创建项目字段，不是 Source Asset selection。不得为了省事把 Source Asset 填进 CreationProject 自然语言字段后假装完成资产建局。

### 4.2 G9-04 Binding Compiler

已有：

```text
exact Manifest
+ base RuntimeDefinition
→ SourceAssetDescriptor
→ hidden binding anchors
→ Expansion module bindings
→ RuntimeDefinition
```

`compileAssetBindingPlan()` 明确不 materialize World / Character semantic content。

因此 G9-05E 必须补齐两者之间缺失的共享引擎层：

```text
Asset Selection
→ exact Source validation
→ explicit role / placement intent
→ deterministic game-local materialization
→ base RuntimeDefinition
→ existing G9-04 binding compiler
```

这层归属 `游戏创建` owner，不归 Creator、不归 Runtime live mutation。

## 5. AssetGameCreationIntentV1

G9-05E 建立最小、Program-owned、可恢复的建局事务状态。它不是 Creator Draft，也不是 AI Creation Project。

建议逻辑合同：

```text
schemaVersion = asset-game-creation.v1
creationRef   = Program-minted stable identity
revision      = CAS revision
lifecycle     = editing | creating | created

worldSnapshot?
characterSelections[]
expansionSelections[]
opening
createdGame?
```

### 5.1 Character selection role

每个 Character exact snapshot 只允许一个角色用途：

```text
bound_only
opening_character
player_character
```

语义：

- `bound_only`：进入 Manifest / Source binding；本阶段不创建 Runtime Character；
- `opening_character`：用户明确要求该角色在开场存在，Final Create 时 materialize 到 opening scene；
- `player_character`：用户明确选择为玩家角色，Final Create 时 materialize 为 `RuntimeDefinition.player`。

同一 exact Character 不得重复出现；同一逻辑 `assetRef` 不得同时选多个版本。

最多一个 `player_character`。

### 5.2 Player Character eligibility

只有：

```text
payload.kind === character
+
payload.playerCharacterSupported === true
```

才可被选为 `player_character`。

`undefined` 表示 Source 未声明支持，不能由 Product 猜成支持；`false` 明确不支持。

任意 Character 均可在满足其它校验时作为 `opening_character` 或 `bound_only`。

### 5.3 Zero-character path

阶段裁定允许 `0..N Characters`，而 Runtime 必须有 player。

若没有 Source-backed `player_character`，opening 参数必须显式提供本局玩家：

```text
localPlayer.displayName
localPlayer.identity
```

可选：

```text
localPlayer.publicBackground
```

它只创建本局 Game-local player，没有 Source lineage，不反向创建 Character Source。

若已选择 Source-backed player，则禁止同时提交第二套 localPlayer authority。

## 6. Exact Source Inventory / Selection

### 6.1 Inventory owner

产品库存只来自：

```text
SourceAssetLibraryStore
```

允许：

```text
listByType('world')
listByType('character')
listByType('expansion')
readExact(snapshot)
```

不得从 Creator Draft Store、文件系统、标题搜索结果或 asset repository 工作区直接选择。

### 6.2 Version UX

UI 必须展示 exact version 和 contentHash 身份。

用户选中的值必须最终提交完整：

```text
assetRef
assetType
version
contentHash
```

若同一 `assetRef` 有多个版本，允许用户明确切换；不得默认用“latest”重新解析已经做出的选择。

### 6.3 World cardinality

Final Create 前：

```text
exactly 1 World snapshot
```

没有 World 或多个 World 均 fail closed。

## 7. Dependency Closure Gate

G9-03 `validateAssetCatalog()` 证明 catalog 级依赖正确，但 G9-05E 还必须证明“本局实际选择集”闭合。

因此新增 Product/Game-Creation 层 selection closure validator，不修改 G9-03 semantics。

### 7.1 Hard dependency

对每个选入本局的 World / Character / Expansion Source：

```text
hard dependency target
```

必须有一个 exact target snapshot 真正进入当前 Manifest 主选择集。

只有“目标 stableRef 在 Source Library 中存在”不算满足。

因为 dependency 只给 stable identity，不给 version，Program 不得自动选择 latest。

缺少 exact target 时：

- Final Create fail closed；
- Product 返回 required target 的 stable identity；
- 若资产库存在多个版本，玩家明确选择一个 exact snapshot；
- 不静默补选。

### 7.2 Target type rules

- hard → `world`：只能由当前唯一 World 满足；若要求另一个 World，v1 fail closed；
- hard → `character`：对应 Character exact snapshot 必须被选入；
- hard → `expansion`：对应 Expansion exact snapshot 必须被选入；
- hard → `library`：G9-05E v1 不具备 Library product binding，fail closed 为 unsupported required dependency。

### 7.3 Optional / Reference

- `optional` missing：允许创建，但作为 deterministic compatibility gap 展示；
- `reference` missing：不阻断创建；
- 不因为 optional/reference 存在就自动选择资产。

### 7.4 Expansion feature_conditional

若 selected Expansion 使用 `feature_conditional`，继续交由 G9-03 existing manifest enablement + catalog validator 判断；G9-05E 不重写该语义。

## 8. Expansion Selection

G9-05E 不要求先有 Expansion Creator，但 Source Library 中若已经存在 formal Expansion Source，可被 exact 选择。

每个选择项直接对应 existing `ResolvedExpansionBindingV1`：

```text
snapshot
packageIncluded
enabledFeatureRefs
enabledModuleRefs
```

Product 初次选择时可以根据 Source 的 `defaultEnabled` 生成**可见的初始建议值**，但：

- 这是 Program-derived UI default，不是 hidden auto-binding；
- 用户可检查并调整；
- Final Create 提交完整 resolved binding；
- existing G9-03 validator 是最终 authority。

如果没有任何 Expansion Source，UI 正常显示“本局不使用拓展包”，Manifest `expansions=[]`。

G9-05F 仍保持未授权。

## 9. Libraries

G9-05E v1：

```text
manifest.libraries = []
```

原因：当前 `SourceAssetLibraryStore` 明确是 Creator 主资产 Source Store，不提供 Library product inventory；G9-04 Library 也只证明 catalog reference integrity，不获得本局 runtime binding/retrieval authority。

不得为满足某个依赖偷偷创建 Library binding。

## 10. Opening Parameters

Final Create 至少需要：

```text
openingLocationLabel: non-empty string
```

可选：

```text
gameLabel
openingSituation
localPlayer（仅无 source-backed player 时）
```

默认：

- `gameLabel` 未提供 → 使用 World `metadata.title`；
- opening region label → World `metadata.title`；
- `openingSituation` 未提供 → 空字符串，不编造具体事件；
- 初始时间继续使用现有 Program default（8:00），除非未来另开产品字段。

不从 World prose 猜“首都”“附近地点”“主角出生点”等位置事实。

## 11. Deterministic Source → Game-local Materialization

这是 G9-05E 的核心编译器，建议命名可按仓库风格调整，例如：

```text
AssetGameMaterializationCompiler
```

它必须纯 Program-owned、Provider calls = 0。

### 11.1 Opening topology

Program 创建最小 game-local scaffold：

```text
1 region
→ 1 opening place
→ 1 opening scene
```

stable refs 由 game identity 派生，不使用 Source `assetRef` 直接充当 Game-local semanticRef。

```text
Source identity != Game-local identity
```

Region label = World title。

Opening Place / Scene label = 用户 `openingLocationLabel`。

Scene publicDescription = `openingSituation` 或空字符串；不得把全世界 lore 假装成当前场景事实。

### 11.2 World Source context

World Source 不被机械解析成多 Region / Place / Scene。

确定性保留：

- metadata.title / summary；
- public sections → immutable player-safe Game Setup fields；
- private sections → server-side `privateSeedContext`，不进入玩家安全投影；
- bounded `contextConstraints.worldConcept` 从 metadata.summary + public sections 做顺序确定的有界投影；
- 任何截断只影响 model context projection，不删除已持久化的完整 public setup field / private seed 数据。

不得按 section 标题猜 runtime ontology。

### 11.3 Source-backed player

当玩家明确选择 `player_character`：

Final Create 才创建 `RuntimeDefinition.player`：

- game-local semanticRef = Program-minted / game-derived；
- displayName = Source `payload.displayName`；
- publicDescription = metadata.summary + public sections 的确定性 player-safe projection；
- privateProfile = private sections 的确定性组合；
- initialSceneRef = opening scene；
- stateSlots = []；
- relationships / knowledge / injuries / office / allegiance = 不推断；
- source provenance 指向 exact Source descriptor。

这是显式 Game Creation materialization，不是 Source binding 自动物化。

### 11.4 Local player

无 Source-backed player 时：

- displayName / identity 只来自玩家 opening parameters；
- no Source descriptor；
- initialSceneRef = opening scene；
- 不创建隐含 Character Source。

### 11.5 Opening characters

只有 role=`opening_character` 的 exact Character Source 在 Final Create 时 materialize：

- Program game-local semanticRef；
- Source displayName；
- public sections → publicDescription；
- private sections → privateProfile；
- initialSceneRef = opening scene；
- no state slots by default；
- no relationship / knowledge / health / allegiance inference；
- source provenance exact。

role=`bound_only` 的 Character 不生成 `CharacterDefinition`，只通过 G9-04 hidden binding anchor 保留本局 Source binding / lineage。

## 12. Game Setup / Context Preservation

不得为了 Context bounded 而丢掉 Source 语义。

### Public

完整 public Source section 可保存为 immutable `RuntimeGameSetupDefinition.fields`，使用 deterministic field ids，例如逻辑形式：

```text
asset:world:<assetRef>:section:<sectionRef>
asset:character:<assetRef>:section:<sectionRef>
```

不得把 private section 放进该玩家安全字段集合。

### Private

private sections 只进入 server-side canonical storage，例如 `privateSeedContext`；键必须稳定且不与 public key 冲突。

### Model Context

现有 `compileContinuityContext()` 的 bounded `contextConstraints` 继续拥有模型可见范围；不得为了“Source 很大”直接把全部 Source 塞给模型。

```text
Full persisted source-derived setup
!= Current bounded model context
```

## 13. Exact Manifest Compiler

Final validation 后构造：

```text
TavernGameAssetManifestV1 {
  schemaVersion: 'tavern.game-assets.v1',
  world: exact selected world,
  characters: all exact selected character snapshots, deduped by logical identity,
  expansions: exact resolved selections,
  libraries: [],
}
```

角色用途不写进 G9-03 Manifest；用途属于 Game Creation intent / materialization plan。

Manifest 必须通过 existing：

```text
validateGameAssetManifest()
validateAssetCatalog()
```

G9-05E 不修改它们的 wire semantics。

## 14. Binding Compiler Reuse

materialization 得到 base `RuntimeDefinition` 后，必须调用 existing：

```text
compileAssetBindingPlan({
  catalog,
  manifest,
  protocolHost,
  runtimeModuleHost,
  baseDefinition
})
```

最终 bootstrap 的 Definition 必须是：

```text
bindingPlan.runtimeDefinition
```

这样：

- World / Character / Expansion exact Source lineage 继续由 G9-04 hidden anchors 证明；
- Expansion runtime module binding 继续由 existing G9-03/G9-04 rails 解析；
- Character binding 本身仍不会 materialize；
- Source v2 后续发布不会改变已创建 game 的 v1 binding。

禁止 E 自行拼第二套 hidden anchor / expansion binding。

## 15. Atomic Create / Exactly-once

资产建局必须有 Program-minted `creationRef` 和 durable lifecycle：

```text
editing
→ creating
→ created
```

至少保存：

- creationRef；
- revision；
- exact normalized selection / opening intent；
- deterministic request fingerprint；
- creating 时 gameId / intended Manifest identity；
- created 时 gameId / sessionPath / createdAt。

规则：

- Final Create 先持久化 `creating`，再 bootstrap；
- bootstrap 完成但响应中断 → 同 creationRef retry 返回同一 game；
- 同 creationRef + 不同 request fingerprint → fail closed；
- bootstrap 未发生且失败 → intent 回到可重试 editing，或保留明确 retry state；
- 不留下 partial game / partial intent；
- 不允许重复点击产生两个 game。

可新建专用极小 store/table；不得污染 Creator Draft Store，也不得把 Asset Intent 假装成 AI CreationProject。

## 17. No-Provider Path

G9-05E core 不依赖模型。

```text
Provider calls = 0
```

也必须完成：

- inventory；
- exact selection；
- dependency closure；
- manifest；
- deterministic minimal topology；
- source-backed player/opening characters；
- binding；
- Runtime bootstrap；
- Session / Save / Restore。

后续可以另开增量，让 AI 辅助建议 opening parameters 或 materialization，但不能成为本阶段正确性的前置条件。

## 18. Save / Continue / Restore / Source Update Gates

必须证明：

1. asset-created game 出现在“我的游戏”；
2. 可进入 Session；
3. 创建 Save；
4. formal turn 后 Restore；
5. exact Source lineage 在 Save / Restore 后保持；
6. 新发布同 `assetRef` v2 后，已创建 game 仍保持 v1 lineage；
7. Source Store 不接受 Runtime 回写；
8. Runtime mutation 不改变 Source Asset digest/content。

## 19. Failure / Security Gates

至少 fail closed：

- Draft identity 冒充 Source；
- snapshot hash 错误；
- wrong assetType；
- zero/multiple world；
- same logical asset multiple versions；
- player role on `playerCharacterSupported !== true`；
- player source + localPlayer 双 authority；
- opening role 引用未选择 Character；
- hard dependency target 未 exact 选择；
- hard Library dependency；
- invalid expansion feature/module selection；
- stale CAS；
- creating replay request fingerprint mismatch；
- duplicate game creation；
- private Source section 出现在 player-safe Product / Narrative Context。
