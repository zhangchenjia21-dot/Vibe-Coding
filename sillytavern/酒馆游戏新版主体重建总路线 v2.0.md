## 3. 长期世界事实模型

当前第 16 号核心：

`16_酒馆游戏_RuntimeWorldMaterialization与当局游戏资产演化裁定_v1.1_2026-08-18.md`

正式三层：

```text
Source Asset Library
↓ snapshot / bind
Game-local Canonical Assets
↓ instantiate / project
Authoritative Runtime State
```

原则：

- Source assets 是跨局模板，不被本局剧情反写；
- Game-local assets 是本局可持续演化的 canonical world definitions；
- Runtime State 管理当前运行状态；
- Model 可以 author candidate / typed patch；Program / Domain Owner 负责现实提交；
- 新 NPC / Place / Item 一旦接受，必须拥有 stable local identity；
- World / Instance Growth != Prompt Growth。

## 4. G9-01｜Compatibility Audit

G8 CLOSED 后第一项。

必须检查：

- 现有 asset-spec / Creator / assets 的 A/B/C 保留/适配/重写分类；
- 是否把 Source Asset 错当成 Runtime 永久只读定义；
- 是否区分 Source Asset / Game-local Asset / Runtime State；
- 是否假定所有 NPC 都来自 Character Card、所有地点都必须预枚举；
- 哪些字段是 canonical anchor / hard constraint；
- 哪些字段允许 local evolution；
- provenance、clone/bind、materialization boundary 与 context contract 如何表达。

## 5. G9-02｜Runtime Asset Binding + Context Orchestration + Game-local Asset / World Materialization Foundation

必须位于 asset-spec vNext Schema Freeze 之前。

### 5.1 Context Orchestration

```text
Player Input
+ pruned Enabled Feature/Module Directory
+ minimal-but-sufficient current context
→ Model-first Router
→ immediate candidates
→ Program structural validation
→ state-mandatory augmentation
→ Current Relevant Set
→ bounded JIT projection
```

同时证明：

```text
Domain Active != Full Definition Registry Visible
Background deterministic progression != Model Activation
Bounded != Starved
```

### 5.2 Game-local canonical asset layer

至少证明：

```text
Source Asset
→ game-local snapshot / instance
→ provenance preserved
→ local mutation allowed
→ source unchanged
```

### 5.3 Dynamic materialization

至少覆盖：

- Dynamic Character；
- Dynamic Place / Scene / Connection；
- existing local asset typed mutation；
- stable identity across turns；
- atomic commit；
- Save / Restore / Recovery；
- player-safe projection；
- world growth with bounded context。

## 6. G9-03｜asset-spec vNext Machine Contract

只有 G9-02 vertical proof 后才冻结。

需要能够表达已经被 Runtime 验证的：

- source provenance；
- clone / bind semantics；
- canonical anchors / hard constraints；
- immutable / mutable / private / runtime-owned boundary；
- materialization eligibility；
- allowed entity kinds；
- ownership / namespace；
- routing / activation / Context Contract；
- information boundary；
- Runtime binding boundary。

不得提前冻结未经 Runtime 证明的万能 DSL / arbitrary state path / Router API / token budget。
