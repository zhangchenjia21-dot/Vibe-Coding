## 2. LIB-G01｜Source Library 更新不得静默改变既有游戏

资料库必须继续遵守 Source / Game-local / Runtime 三层分离。

```text
Library Source Update
!= Existing Game Auto Update
```

当某一局游戏引用或绑定某个资料库时，G9-03 必须提供足够的版本与完整性语义，使既有游戏能够证明自己使用的是哪个资料版本。

至少需要在机器协议层表达或可推导：

- stable library identity；
- source version；
- content hash / integrity identity；
- stable entry identity；
- 本局绑定 / 引用所依据的 source revision identity；
- future explicit rebind / migration 的可扩展挂点。

默认规则：

```text
作者发布资料库 v2
!=
所有使用 v1 创建的既有游戏自动改读 v2
```

如果未来允许既有游戏升级资料库版本，必须是显式、可验证、可迁移的 rebind / migration 行为；不得通过外部 Source 内容更新静默改变存档的模型参考基线。

目的：保持长期会话、Save / Restore / Branch / Recovery 与重放语义的可解释性和稳定性。

---

## 3. LIB-G02｜Retrieved Library Slice 永远是 Reference Projection

正式冻结：

```text
Library Source
→ bounded retrieval / filtering
→ Retrieved Reference Projection
```

并且：

```text
Retrieved Reference Projection
!= Game-local Canonical Truth
!= Runtime State
!= Formal Outcome
```

资料检索结果可以：

- 给 Creator 提供研究参考；
- 给模型提供时代 / 制度 /历史背景；
- 给正式领域定义的创作或候选生成提供来源；
- 支持一致性检查和解释。

但资料检索结果本身不能：

- 直接覆盖世界包 / 当局游戏定义；
- 因“资料里这样写”就改变 Runtime State；
- 绕过 Program / Domain Owner mutation path 成为正式现实；
- 把历史参照强制解释成当前世界必然发生的未来。

正式链仍应是：

```text
Reference Projection
→ Model / Creator proposes candidate
→ Program / Domain Owner validates
→ explicit canonical / runtime commit when appropriate
```

因此资料库是“参考依据的 Owner”，不是“当前世界现实的 Owner”。

---

## 4. LIB-G03｜资料可见性不能退化为单一 public / private

资料库协议需要保留“谁能以什么职责读取资料”的语义空间。

长期至少必须概念上区分：

```text
Creator / Author Reference
Model Worldbuilding Reference
Player-visible Knowledge
Character-known Knowledge
```

这些集合可以重叠，但不能默认相等。

示例：

```text
某条原历史结局
可供 Creator 检查时代一致性
可供穿越者历史辅助读取
但普通本地 NPC 不一定知道
普通玩家角色也不一定自动知道
```

因此 G9-03 不应只靠一个笼统的：

```text
visibility = public | private
```

试图解决全部资料信息边界。

本轮不要求冻结最终字段枚举，但统一协议必须留下可扩展的 audience / usage / disclosure 语义挂点，并继续遵守：

```text
资料库包含某事实
!= 玩家知道
!= 角色知道
!= 当前模型职责可见
```

具体 Creator / Runtime / 玩家知识产品行为仍在对应后续阶段验证后冻结。

---

## 5. 角色卡 / 世界包与资料条目的重复不等于双重 Truth

允许同一现实对象同时存在：

```text
资料库中的历史人物条目
= reference / research object

角色卡中的人物
= game definition object
```

允许角色卡 / 世界包引用资料条目作为 provenance / reference / inspiration，但正式游戏对象必须保持自己的 stable identity 和 Owner。

禁止为了“去重”把角色卡、世界包或正式领域定义降级成资料条目的薄引用，从而让资料库间接成为游戏定义 Authority。

---

## 6. G9-03 传播要求

G9-03 冻结统一资产 / 资料资源协议时，除 #18 v1.2 原有要求外，必须额外检查：

1. Source Library 更新是否会静默改变既有游戏；
2. library binding 是否有版本 / hash / stable entry identity；
3. retrieved slice 是否明确是 Reference Projection；
4. Reference 是否不能绕过 Game-local / Runtime Owner；
5. audience / usage / disclosure 是否有长期扩展空间；
6. 是否避免把角色卡 / 世界包降级成资料库引用壳；
7. 是否继续不冻结 embedding、chunk size、向量维度、排名算法、任意查询 DSL 或具体 RAG Provider API。

原则：

> **协议冻结“资料是谁、来自哪、怎么引用、哪类职责可以读取”；不要过早冻结“未来具体怎么搜”。**

## 8. 最终冻结

```text
资料库
= Reference Resource Layer

Source update
!= existing game silent update

Retrieved slice
= Reference Projection
!= Runtime Truth

Creator Reference
!= Model Reference
!= Player Knowledge
!= Character Knowledge

协议冻结 identity / version / reference / audience seam
!= 提前冻结 retrieval implementation
```

> **资料库的长期价值来自“可复用的大规模参考知识”，它必须补充正式世界，而不是成为第二套正式世界。**
