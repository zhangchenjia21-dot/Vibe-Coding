# 酒馆游戏 G5 长期连续性与玩家授权收口裁定 v1.0

> [!abstract] 裁定结论
> `G5｜长期世界连续性` 于 2026-08-15 通过工程 Gate、独立审核与项目所有者真人体验裁定，正式记为 **PASS / CLOSED**。
>
> 本文件不重写 World OS Core、FC2 或 H.0A，而是记录新版 Runtime 在 G5 实际验证后形成的当前实现边界、测试解释规则、授权架构止损规则，以及推迟到 G8 的自然输入体验改进。

---

## 一、阶段状态

正式阶段状态：

```text
G1｜真实模型兼容性          PASS / CLOSED
G2｜最小世界运行内核        PASS / CLOSED
G3｜正式世界能力扩展        PASS / CLOSED
G4｜程序判定与 Dice         PASS / CLOSED
G5｜长期世界连续性          PASS / CLOSED
G6｜Save / Continue / Restore  ACTIVE
```

G5 关闭以后，不因普通安全语义差异、偶发多一次确认或生僻表达 clarification 重新打开 G5。

## 二、G5 已冻结的长期连续性成果

以下能力已经通过实现、自动化、真实 DeepSeek 与真人路径验证，作为后续阶段的正式上游基础：

1. **Character Knowledge 是正式权威状态。**
2. **World Truth ≠ NPC Knowledge ≠ Player Knowledge。**
3. Pending Commitment 具有独立正式语义。
4. Pending World Action 具有独立正式语义。
5. Background Progression 只能依据正式状态、目标、计划、规则或触发推进。
6. Continuity Context 保持 bounded：
   - recent Turns `<= 4`；
   - relevant Events `<= 6`；
   - 不发送完整 transcript。
7. 当前 authoritative state 优先于 old history。
8. Semantic private context 与 Narrative player-safe context 分离。
9. Program whitelist 只允许已批准 Disclosure 进入 Narrative。
10. Program Final Outcome 在 Narrative 前确定。
11. Program owns facts；Model writes prose。
12. Natural Narrative 不能退回程序模板回显。
13. No Phantom World Change 是正式不变量。
14. G4 Resolution 链继续保持单一正式结果事实源。
15. `read_only_query`：
    - 不形成 Formal Turn；
    - 不增加 revision；
    - 不推进 worldTime；
    - 不产生 Event；
    - 使用 ephemeral player-safe response。
16. Dialogue / Observation / Inner Expression 可以形成 Formal Turn。
17. Playtest Shell 继续只消费玩家安全投影。
18. Atomic Commit、rollback 与 hidden disclosure boundary 继续保持。

## 三、玩家主动世界变化的当前安全边界

### 3.1 两级授权架构

当前 Runtime 采用两级授权：

#### Tier 1｜Program Deterministic Direct Fast Path

Program 只对少量：

- 整句；
- 单动作；
- 高置信；
- 无否定；
- 无愿望；
- 无问句；
- 无条件；
- 无撤回；
- 无第二个世界变化；

的常见明确表达提供 Direct Fast Path。

Fast Path 是体验优化，不是完整 NLP 引擎。

#### Tier 2｜Model Candidate → Program Confirmation

Program 无法确定证明、但 Model 能理解的合法 world-changing Candidate，当前进入 Program-owned Confirmation。

Confirmation 保持：

- exact candidate-bound；
- revision-bound；
- capability-bound；
- single-use；
- cancel 无副作用。

模型返回 `execute_now` 本身不构成直接执行授权。

### 3.2 Candidate Directory 与 Authorization 分离

Program 从正式世界生成玩家安全、当前可行的 Candidate Directory。

Candidate Directory 回答：

> 当前世界允许尝试什么？

Authorization 回答：

> 玩家当前输入是否授权现在执行？

Program 不能因为自己没有先用 Regex 识别动作，就从模型可选能力中删除该 action family。

### 3.3 正式提交权仍归 Program

即使后续产品体验选择更信任模型的自然语言理解，以下边界仍不可改变：

```text
Model interprets / proposes
→ Program validates Capability / rules / authority
→ Program determines Formal Outcome
→ Atomic Commit
→ Narrative realizes committed result
```

“更信任模型理解玩家语言”不等于“把正式世界提交权交给模型”。

## 四、No Phantom 与多动作安全

### 4.1 No Phantom World Change

任何 Narrative 中已经发生的主动世界变化，都必须拥有匹配的 Program-owned Formal Outcome。

至少包括：

- Move；
- Item Transfer；
- Show Item；
- Item Interaction；
- Wait / Time progression。

Program Outcome 与 Narrative 不一致时，必须 fail closed；Narrative 不能替 Program 补造世界变化。

### 4.2 当前多动作输入边界

G5 当前实现优先保护“不偷偷 partial commit”。

例如：

> 返回酒馆，并睡到第二天。

如果 Runtime 当前只可靠识别其中一个 world-changing Candidate，不得静默只执行其中一项并假装整句完成。

现阶段出现单动作 Confirmation 属于**安全但体验不足**，不再视为 G5 blocker。

完整的自然多动作顺序执行作为 G8 产品化体验能力处理，前提是继续保持：

- 一个玩家输入最多形成一个正式 Turn；
- 动作顺序明确；
- Capability 分别成立；
- Formal Outcome 可验证；
- 最终提交原子；
- 失败时不得半提交。

## 五、真实模型测试解释规则

### 5.1 Hard Safety 与安全语义差异必须分开

真实模型的 semantic variation 不等于安全失败。

例如玩家输入：

> 我能往酒馆门口走吗？

在当前有可见 NPC 的 Scene 中，至少存在两类合理、安全解释：

1. 系统能力询问 → `read_only_query`；
2. 对当前 NPC 的询问 → Dialogue Formal Turn。

只要没有：

- 执行 Move；
- 执行 Wait；
- 修改 Item；
- 产生未经授权 world-changing outcome；
- 泄露 private Knowledge；
- 产生 Phantom World Change；

就不能仅因 Dialogue / Read-only 分类不同而记为 Hard Safety failure。

### 5.2 G5 继续作为硬 Gate 的内容

- Player Agency violations = 0；
- Phantom World Changes = 0；
- Hard Safety failures = 0；
- Confirmation Candidate 与执行一致；
- stale Confirmation 不可执行；
- Capability-invalid Candidate 不可执行；
- Hidden Knowledge 不泄露；
- Atomic Commit；
- 常见明确动作具有可用 Direct Fast Path；
- Model-only paraphrase 至少可以安全进入受控路径；
- Confirmation cancel 无世界副作用。

### 5.3 不再单独作为 G5 blocker

除非频繁到真实游戏不可玩：

- 某个歧义问句被理解为 Dialogue 而非 Read-only；
- 某个自由表达多一次 Confirmation；
- 某个生僻表达 clarification；
- 偶发安全语义差异；
- 某个不常见 paraphrase 未走 Direct Fast Path。

## 六、授权架构止损规则

G5 关闭后，授权架构默认冻结。

不得因为以下体验差异重新进入“一个失败句式 → 一个 Regex → 再次 UAT”的循环：

- 多一次确认；
- Dialogue / Read-only 安全差异；
- 生僻说法 clarification；
- 某个 paraphrase 没有 Direct Fast Path；
- 模型偶发但可安全纠正的理解偏差。

只有以下情况允许重开玩家授权安全边界：

1. 未经授权 world-changing commit；
2. Confirmation 显示 A 却执行 B；
3. stale Confirmation 被执行；
4. Capability 被绕过；
5. Phantom World Change；
6. Hidden Disclosure；
7. partial commit；
8. 常见明确表达高频无法使用，已达到真实游戏不可玩程度。

## 七、G8 已登记体验债：自然输入、撤回与多动作

项目所有者在 G5 真人体验后明确指出：

> 不应为了让模型“绝对不理解错”而无限增加前置确认、规则和维护成本。对普通自然语言交互，可以更信任模型的理解能力；更好的产品纠错手段应包括玩家可见的撤回和重新输入。

因此以下内容正式登记到 G8，而不回头阻塞 G5、G6、G7：

### 7.1 减少过度 Confirmation

目标体验：

- 正常、低风险、自然表达不频繁弹出“我理解为……”；
- Model interpretation 可以承担更多自然语言理解；
- Program 继续拥有 Capability、Judge、Formal Outcome 和 Commit 权限。

### 7.2 玩家可见“撤回 / 重新输入”

目标体验：

- 玩家发现系统理解错后，可以快速撤回最近一次可安全撤销的操作；
- 回到明确稳定状态；
- 重新输入。

实现顺序必须建立在 G6 的 Save / Restore 正式语义以及 G7 的 Recovery / idempotency 基础之上。

“撤回”不是允许静默改历史，也不能绕过世界一致性和正式恢复语义。

### 7.3 单条输入中的多个连续动作

支持类似：

> 返回酒馆，并睡到第二天。

这类自然、顺序明确的多动作表达。

目标不是建设万能 Multi-action Planner，而是为真实高频玩家表达提供受控的顺序执行语义。

必须继续满足：

- 不偷偷挑一部分执行；
- 不把多个世界变化拆成无法回滚的半状态；
- 一个玩家输入最多形成一个 Formal Turn；
- Program 最终拥有完整 Formal Outcome；
- Atomic Commit。

## 八、对 G6 的边界

G6 当前只处理：

- Save；
- Continue；
- Restore；
- Branch 正式语义；
- 完整 authoritative state 恢复。

G6 不顺手修改：

- G5 授权架构；
- Confirmation UX；
- 多动作输入；
- “撤回”产品按钮；
- G8 正式交互。

这样可以避免再次在已通过的上游阶段长期停留。

---

## 九、生效结论

自 2026-08-15 起：

```text
G5 = PASS / CLOSED
G6 = ACTIVE
```

长期有效的总原则是：

> **安全要求关注“模型错误能否污染正式世界”，而不是要求模型永远产生唯一语义解释。**
>
> **产品体验允许逐步增加对模型自然语言理解的信任，但正式世界的验证、结果与提交权继续由 Program 持有。**
>
> **当硬安全 Gate 已经通过，应冻结上游架构，把可逆的体验改进登记到最合适的后续阶段，而不是无限重构。**
